## 5. 接手必须懂的 6 个机制

### 5.1 有限推力点火（第 11 轮起全面取代瞬时脉冲）

* `World#finiteBurn(c, opt)` —— 闭环 VTBG（`target` 固定惯性速度 / `targetFn` 动态）
  或开环（`dirFixed` + 速度判据）。`opt.maxT` 是硬上限。
* `World#updateBurn(c, h)` 每个积分步推进；`World#endBurn(c, reason)` 关机。
* `World#centerBurn(c, r0, vPre, dv, solveAt)` —— **燃烧中心化**：把脉冲点放在
  `t + T/2`，使实际关机点落在脉冲点上。不做这件事，远地点方向差 24.5°（=到达月球差 15.9 万 km）。
* `estimateBurnSecs(c, dv)` 火箭方程估燃烧时长；`affordable(c, dv)` 判断油够不够。
* ⚠ **`chooseStep()` 必须在任何 burn 的"第一帧"把步长压到 ≤0.5 s**
  （`if (cb.active) h = Math.min(h, 0.5)`，终末段再按 `termH` 压）。
  漏了这条，小点火的 `maxT` 会在第一步就被判超时 → `ignite()` 一点油都没烧，
  现象是"报告已启动 19.4 m/s，质量一动不动"。**这是第 13 轮最隐蔽的 bug。**

### 5.2 自动演示引擎（`11-demo.js`）

* `Demo.tick(dt)` 推进 `DEMO.stepT` / `DEMO.timer`（都是**仿真秒**）；
  `enterStep()` 跑每步的 `enter`；完成靠 `st.done()`；超时靠 `st.timeout`；
  **连续 3 次超时 → `Demo.stop('stuck')`**。
* `driveGuides(dt)` 分发到 `descentGuidance` / `lunarAscentControl` / `rendezvousControl`。
* 铁律（`01` 文档第 4 节有完整版，务必读）：
  1. 演示要用的接口**必须真导出**，禁止 `app().xxx && app().xxx()` 式的静默空转；
  2. 步骤切换后**当帧要再驱动一次** `driveGuides`；
  3. 倍率只能走 `app().setWarpValue(v)`，不能直接写 `world().warp`；
  4. 演示异常**必须显式报出来**（红色横幅 + 原因，留 20 秒）；
  5. `Demo.tick` **不许吞 `done()` 的异常**（第 13 轮修：现在会把步骤名和错误写进飞行日志）。

### 5.3 "演示确定性"三件套（第 13 轮新增，**只作用于自动演示**）

设计原则（用户明确要求）：**自动演示每次必须播完同一条完整链路；手动飞走真实物理。**

| 函数 | 做什么 | 用在哪一步 |
|---|---|---|
| `demoRndzNormalize(chaser, target)` | 把上升级摆到与指令舱**共面同轨、相位落后 30°** 的固定状态（绕轨道法向 Rodrigues 旋转 −30°，并复位交会状态机所有字段） | 交会开始前 |
| `demoRndzCloseOut(chaser, target)` | 制导收不拢时，把上升级同步到目标**后方 100 m、接近率 2 m/s**（满足对接判据 ≤200 m / ≤20 m/s） | 交会有 350 000 s 的时间兜底 |
| `demoReturnAssist(c)` | 把服务舱摆到**地心 20 万公里**处的返回椭圆（月球 SOI 只有 6.6 万 km，这里引力可忽略） | TEI 闭环校验连续失败 / 返回滑行走满 4 天 |

另有演示裕度：交会前把上升级补到 3 200 kg；TEI 前把 SPS 补到 12 000 kg
（原来 6 500 kg，第一发 TEI 就烧掉 5 500 kg，重试时只剩 930 kg 修不动）。

> 这些同步**必须在日志里写明"演示同步"**，不能假装是制导算出来的。

### 5.4 交会状态机（`rendezvousControl`，`03-physics.js`）

`match → phasing → settle/chase → tpi → close`，关键字段：
`_rndzSt / _rndzCool / _rndzChaseA / _rndzDv / _rndzClose / _rndzCloseP0 /
_rndzWant / _rndzTpiN`，驱动函数 `rndzDrive(world, c, ms, cr, cv, wantA, strict, fixed, tolKm)`。

当前能力边界：**制导能稳定收到约 3.6 km，收不进 150 m 的对接判据**，
所以自动演示靠 `demoRndzCloseOut` 收尾。这是"手动飞允许失败、演示必须成功"的地方。

### 5.5 TEI / 返回

`transEarthInjection(world, c, dvKmS)` 的建模范式（**推倒重来过三次，改动前务必读 `05` 文档 6.8/6.9**）：

1. 相位闸门：只在"环月轨道速度与月球公转方向接近反向"的点上点火
   （`dot(unit(vrel), unit(moon.v)) > -0.55` → 返回 `failed`）；
2. 解析种子（顺行切向、`v∞ = 月球公转速度 − 返回速度`）+ 局部数值精修，
   评价函数要求**真的脱离月球 SOI** 且是**束缚轨道**（`e < 0.995`）；
3. **在燃烧中心化的脉冲点上求解**（不是当前时刻）；
4. 点火后闭环校验 `returnIsValid(world, c)`：外推 6 天 → 必须脱离月球 SOI、
   地心 `e < 0.995`、近地点落在再入走廊 `[0.9 R⊕, R⊕+800 km]`；
   不合格就**按实飞状态重解重打（最多 5 次）**，仍不合格走 `demoReturnAssist`。

⚠ 三个致命陷阱（都真撞过）：
* 用**地心兰伯特**给低环月轨道上的飞船算 Δv → 方向≈地心速度反方向 = **月球参考系里逆行点火** → 直接撞月；
* 把燃烧当瞬时脉冲 → 燃烧 300~400 s 期间飞船前进约 480 km（≈轨道半径 1/4），算的和飞的不是同一条轨道；
* 解析式漏掉双曲线的转向角（`v∞≈0.84 km/s` 时 `δ≈104°`）→ 只能当种子，必须数值精修。

### 5.6 i18n 与界面布局

* 词表 `DICT.zh` / `DICT.en` **条数必须一致**（bughunt 会输出 `词条 zh/en = N/N`）；
  HTML 用 `data-i18n`，**画布上画的字也必须走 `APL.t('key')`**，否则英文模式"半中半英"。
* `?lang=en|zh` 可强制语言。
* ⚠ **启动自检脚本会来回切一次语言做验证**（`index.html` 末尾内嵌脚本），
  第 14 轮已改成"记住原语言 → 切回去"，并用 `APL.__silentLangSet` 让
  `07-app.js` 的语言监听器在自检期间不写日志。改这段时别把这两条弄丢。
* 顶栏（`#topbar`）的布局规则是**刻意**的：`flex-wrap: wrap` + `min-height` +
  子项 `flex: none` + `button { white-space: nowrap }`。

  文字会被折行/裁掉（第 14 轮用户反馈的原问题）。

### 7.1 简化模型（长期声明，与 README 一致）

## 8. 红线（违反即返工）

1. **禁止删除工作区以外的任何东西**（用户明令）。工作区内的产物一律不删，
   临时文件挪进 `.tmp/` 而不是删除。
2. **自动演示不许做成"概率性成功"**，也不许做成"必定失败"。
   演示必须每次播完；手动飞允许失败，但失败必须是安全的（明确报错、
   不抛弃服务舱、不打错飞行器）。
3. 演示里的"脚本同步"**必须**在日志里标注为演示同步，不得伪装成制导结果。
4. 架构铁律：Python 只做宿主；JS 按 `00-`…`11-` 前缀顺序加载、全局 `APL`、不用 ES module。
5. 新增任何资源文件必须同步加进打包配置（`tools/build_exe.py` 与 `Apollo11LunarLanding.spec` 两处）。
6. 教程/引导**绝不自动播放**；不要在 bootstrap 里用 `textContent` 硬编码覆盖带 `data-i18n` 的元素。
7. 改物理参数前先对照 `03` 文档第 3 节的"已校准真实数值"表，**不允许劣化**。
8. 一次性补丁脚本**先用 Write 落成 `.py` 文件再跑**，不要用 Bash heredoc 内联
   （heredoc 会吃正则反斜杠，导致"静默无效"）。
9. 稳定性结论要**重复跑 ≥3 次**；关键数值要和物理预期对齐（例：TLI 该掉 ~76 t
   推进剂，只掉 667 kg 就是没点火）。
