## 2. 有限推力点火（`03-physics.js`）

### 2.1 为什么要改

真实的 TLI 烧 347 s、LOI-1 烧 357.5 s、TEI 烧 151 s。原来的 `impulsiveBurn`
一步给完 Δv，等于"燃烧时间 0、重力损耗 0"，而且解释不了"为什么飞控要提前算
好点火时长与点燃时刻"。

### 2.2 走过的弯路（**非常重要，别再踩**）

第一版做了"**闭环制导**：每一步用当前状态重解一次兰伯特，把推力对准目标速度"。
**这条路走不通**，实测后果很严重：

* 地月转移对初始条件极其敏感 —— 每 **1 m/s** 的速度误差 = 到达月球 **1 700 km**
  的位置误差（`M.lambert` 自身的往返精度是 1e-7 km，所以问题不在求解器）。
* 飞船一边烧一边前移，从"新位置"重解出来所需速度每步跳几十 m/s，制导永远追不上。
* 实测：TLI 一直烧到 **1 800 s**（maxT）都没关机，把 S-IVB 的 106.4 t、登月舱
  下降级的 8.2 t、上升级的 2.35 t、服务舱的大半推进剂**全部烧光**。

第二版试了"**打靶法解常值推力方向**，使燃烧末状态落在目标轨道上"。
**也不通**：2 个自由度的推力方向满足不了"位置 + 速度"三个约束，实测残差停在
100 m/s 量级，甚至把推力方向拧到水平面下 41°。

### 2.3 现在的做法（**正确且稳定**）

```
① 燃烧中心化（World#centerBurn）
   有限点火必须**提前半个燃烧时长**点燃，关机点才落在理想脉冲点上。
   实测：不中心化时转移轨道远地点方向差 24.5°（= 到达月球差 15.9 万 km），
   中心化之后降到 5.1° 以内。
   实现：脉冲点 = 沿点火前轨道滑行 T/2；目标速度按火箭方程预算 T。

② 推力方向 = 脉冲点上的理想脉冲解方向 (v_imp − v_pre)（真实 TLI 姿态，
   实测仰角 +8~+15°，含"抬头"成分）

③ 关机判据 = **速度达到目标轨道在该半径上的速度**（标量判据）
   —— 真实运载器/飞船的"速度关机"制导，稳定、单调、天然吸收重力损耗。
   ⚠ 不要改成"速度矢量判据"：推力方向是定死的，垂直分量本来就控不了，
     矢量判据永远收敛不了（实测烧满 maxT 把推进剂全烧光）。
   ⚠ 燃烧时长要有硬上限（`maxT ≤ 3× 火箭方程预算`）：目标速度随半径变化，
     某些几何下判据会一直不满足（实测 DOI 想烧 19 m/s 却烧了 900 s / 4 014 m/s）。

④ 所有大机动统一走 `World#startFiniteManeuver(c, 目标轨道, opts)`
   TLI / MCC / LOI / LOI-2 / 平面机动 / DOI / TEI 都是这一个入口。
```

### 2.4 相关 API

| 方法 | 作用 |
|---|---|
| `World#startFiniteManeuver(c, orb, opts)` | 启动一次有限机动（orb 由 `orbitFromState` / `lunarAimPoint` 给出） |
| `World#centerBurn(c, r0, vPre, dv, solveAt)` | 燃烧中心化：脉冲点 + 关机点目标速度 |
| `World#estimateBurnSecs` / `burnSpeedTarget` | 燃烧时长预算 / 目标速度 |
| `World#finiteBurn(c, opt)` | 底层点火；`dirFixed`+`speedOrb` = 开环模式 |
| `World#impulsiveBurn(c, dv, dir)` | **保留**给"规划与估算"用（计算器、霍曼式估算） |
| `World#onBurnStart / onBurnEnd` | 应用层日志钩子（飞行日志里会打印燃烧时长/耗油/重力损耗） |

## 3. 月球自转（`02-astro.js`）

原来的 `moonFrame()` 直接拿**瞬时轨道法向**当月球自转轴。真实月球不这样：
Cassini 第一定律要求自转轴、轨道法向、黄极三者共面，自转轴相对黄极只倾斜
**1.543°**（相对轨道面 6.688°），并随升交点做 18.6 年进动。

现改用 **IAU/IAG 月球自转模型**（α₀ / δ₀ / W 的周期项保留主项，E₁ 项主导）：

```
α₀ = 269.9949 + 0.0031T − 3.8787 sinE₁ − 0.1204 sinE₂ + 0.0700 sinE₃ − …
δ₀ =  66.5392 + 0.0130T + 1.5419 cosE₁ + 0.0239 cosE₂ − 0.0278 cosE₃ + …
W  =  38.3213 + 13.17635815 d + 3.5610 sinE₁ + 0.1208 sinE₂ − 0.0642 sinE₃ + …
```

**校验（本项目实测）**：极轴·黄极 1.537°（真实 1.543°）；极轴·轨道法向 6.658°
（真实 6.688°）；一个恒星月后月固点回到原方向（偏差 0.03°）；
着陆瞬间静海基地太阳高度角 **10.34°**（NASA 飞行计划 10.3~10.5°）。
旧模型给 9.79°，偏低约 0.6° —— **这一条是本次改造最硬的一项验证**。

`moonFrame()` 仍返回 `{x,y,z,state,libration,omega}`，调用方不用改；
`libration` 现在是真的"视经度天平动"（地心方向在月固系里的经度，±8° 内摆动）。

## 4. 地月转移瞄准（`World#lunarAimPoint`）

1. **B 面偏置**：目标不是月心，而是距月心 b 的一点，
   `b = rp·sqrt(1 + 2μ/(rp·v∞²))`。
   ⚠ 偏置方向必须垂直于 **月心系 v∞**。早先用"地心到达速度"当 B 面轴是错的 ——
   到达时地心速度只有约 0.19 km/s（几乎沿径向），而真正的 v∞ ≈ 1.0~1.3 km/s
   几乎与月球公转反向，两者差近 90°，做错会让到达平面偏 8° 以上。
2. **2 参数 Newton**（数值雅可比，6 次迭代，每次 3 段数值传播，约 0.9 s）：
   用**与仿真同一套引力**积分整段转移，把"到达时刻的实际月心相对位置矢量"
   调到"垂直于实际到达速度、长度 = b"。月球引力影响球半径 66 183 km，
   飞行器到达前好几小时就被拽偏，纯解析解到达时能差几十度
   （而 49° 的平面误差要靠 2·v·sin(24.5°) ≈ 1.35 km/s 的平面机动才能补，
   服务舱根本掏不出来）。
3. 燃烧中心化用的脉冲点/目标速度由 `centerBurn` 给出。

**实测残差**：转移轨道远地点指向误差 0.3~0.5°；
到达近月点高度 95 km ~ 9 500 km（见第 6 节"已知限制"）。

## 5. 其它

* **二级以后的关机/交班**：`advance()` 里每步先 `updateBurn()` 再 `ignite()`，
  顺序不能反（否则油门与推进剂对不上）。
* **开环模式**的 `b.speedOrb / b.speedBody` 必须**显式拷进 burn 对象** ——
  曾经漏拷，结果关机判据被跳过、燃烧一路烧到默认的 600 s（烧掉 109 t）。
* **相位判据必须用"跨越检测"**，不能用快照：演示倍率可以到 ×2000
  （一帧 33 s 仿真时间），快照式判定会直接跳过窗口 —— 实测 M4 因此把 PDI
  提前到 374 km、下降剖面变陡而坠毁。现在是 `sitePhaseCos()` + `phUp` 计数器。
* **小于 5 m/s 的残差不再补点**：速度判据在"目标速度随半径变化"的几何下
  会变成一次停不下来的小燃烧（实测把服务舱最后 3.3 t 白烧掉）。

## 5.5 第 11 轮补丁（同一轮内后续修掉的）

* **捕获/降轨的速度目标必须用"以当前半径为远点的椭圆"**：
  `v = sqrt(2μ·rp/(r(r+rp)))`。用"固定半长轴 a"的写法时，飞船一边烧一边往外走，
  一旦走出 a 的范围（`2/r − 1/a < 0`）目标速度就**无定义**，速度判据永远不满足，
  点火一路烧到 maxT 超时 —— 实测 LOI 就是这样捕获失败的（然后在引力影响球边缘
  飞过去，整条 M5 链路全废）。见 `World#burnSpeedTarget` 的 `orb.periR` 分支。
* **这类机动的推力方向要由"当前速度比目标快还是慢"自动决定**（`opts.retro`）：
  快了反推、慢了加速。于是同一段制导既能压近月点、也能把它抬回来 ——
  实测 LOI 有时会刹过头把近月点压到月面以下，自动定向之后第二遍能自己修回来。
* **演示脚本的触发阈值不能随便调**：为了测试把 LOI 的 `alt > 45000` 改回
  `alt > 2500` 之后忘了还原，结果 M5 的 LOI 整段不触发（到达近月点 7 061 km，
  永远进不了 2 500 km）。改演示参数时请连同 `05`/`03` 一起核对。
* **【交会辅助点火】改成闭环制导**（原来是一次瞬时脉冲 Δv，与其它机动不一致，
  玩家也看不到过程）：现在接通的是和自动演示同一条 `P.rendezvousControl`，
  再点一次关闭，到位（≤150 m、≤20 m/s）自动断开并提示可以去对接。
* **界面补上【切换飞行器】**：以前 `App.switchCraft` 只有演示引擎调用，
  界面上根本没有这个按钮，玩家分离完登月舱就开不动它。

## 6. 已知限制（诚实记录）

> 本节结论已在第 11 轮末（见 6.5）复核过一遍，下面写的是**当前**状态。

1. **到达月球的瞄准残差 ~10³ km**。TLI 用有限推力（固定姿态 + 速度关机），
   关机残差是几 m/s，而地月转移的放大倍数是 1 m/s → 1 700 km。现在靠
   **MCC 数值瞄准 B 面点**把它收回到近月点 1 200~5 500 km（不同出发几何
   不同）。真实任务靠发射窗口 + 多次中途修正做到几十公里。
   * 后果：LOI 的捕获高度比真实的 111 km 高，Δv 约 1 040~1 100 m/s
     （真实 LOI-1 是 889 m/s），LOI-2 也相应贵一些。**这是服务舱推进剂
     余量被调高的直接原因（见 6.5.5）。**
2. **M5 全流程状态（第 11 轮末实测）**：
   * ✅ 起飞 / 入轨 / TLI / MCC / 接近月球 / SOI / LOI（近月点 200 km）/
     LOI-2（150 km 环月轨道）/ 分离 / 下降轨道窗口 / DOI / PDI / **着陆成功**
   * ✅ EVA / **上升级入轨**（15×136 km 一线）
   * ⚠️ **交会对接仍未自动完成**：轨道匹配（以目标半长轴为基准）+ 相位调整
     （ΔP/Δa/Δv 三式）+ 兰伯特（< 80 km）+ 相对速度闭环（< 2 km）这套
     组合已经能把两器拉到**同一条轨道**上，但 40 000 s 的超时内还收不到
     150 m。点火次数有硬上限（14 次）—— 几何不好时制导会"改来改去"，
     早期版本因此把上升级打进逃逸轨道；现在宁可停在一条正常环月轨道上
     （实测 56×247 km），演示跳过本步并正常结束。
   * ⚠️ 交会一旦没成，后面的对接 / TEI / 返回 / 溅落也会跟着超时跳过。
   * 已试过并否掉的办法：① 只做"朝目标推一把"的比例导引（旋转参考系里
     等于把飞船推离轨道，实测登月舱被推着往月面掉）；② 让两台飞行器同时
     对开（互相把对方当"要匹配的轨道"，高度一起往上跑，实测被抬到
     1 173×1 515 km）；③ 匹配与相位用同一套阈值（两者互相打架，推进剂烧光）。
3. **M4（专门的降落任务）是回归下限**：落点 37 m。注意它在高倍率下
   **偶发**坠毁（同一份代码两次跑，一次 37 m、一次 5 480 m）—— 这是
   动力下降末段对分帧的敏感性，属于既有问题，不是本轮引入的。
4. **有限点火的姿态是常值惯性方向**（开环）+ 速度关机，没有真正实现
   "迭代制导期间的小姿态修正"。
5. **RCS / 姿态动力学仍未建模**：姿态是瞬时对准（无速率限制、无 RCS 消耗）。
6. 地球大气仍是分段指数模型；月海质量瘤（低阶月球重力场）未建模。

## 6.5 第 11 轮末 · 把 M5 全流程打通（六个真 bug）

这一轮的目标是"五个任务全部跑通 + 查 bug"。过程中挖出六个**真正的 bug**，
其中第一个是整条 M5 链路的元凶。改完之后的实测状态见第 6 节。

### 6.5.1 ★ `cross(rHat, upS)` 在飞船飞到着陆点正上方时退化成噪声

`lunarOrbitAlign` / `lunarPlaneSetup` 用
`nT = unit(cross(rHat, upS))` 求"过站轨道面"的法向。可是 **LOI 恰好发生在
近月点，而近月点又被 TLI 瞄在着陆点上方** —— 两个单位矢量几乎平行：

```
rHat = (0.887, 0.399, 0.232)   upS = (0.891, 0.417, 0.178)
|cross| = 0.0567               nT 与真实轨道法向夹角 = 99.8°
```

于是闭环制导把速度往**月球极轴方向**拉：实测 LOI 的初始速度误差
1.10 km/s 被算成 1.60 km/s，18.4 t 的 SPS 全打光、只换来一条 169×4 829 km
的轨道，后面所有步骤全部没油。

**修法**：退化时改用"速度方向 × 站点方向"定面（只要飞船是掠过而不是直冲
站点就不会退化）。修完 LOI 的 Δv 从 1 630 m/s 回到 1 062~1 096 m/s。

### 6.5.2 MCC 瞄准：不能再拿"近月点高度"当目标

实测敏感度（T+2 800 s 处，顺行方向）：

| Δv | 到达近月点 |
|---|---|
| 0 | 4 705 km |
| +10 m/s | **−1 086 km** |
| +50 m/s | 11 282 km |

周期只有几 m/s —— 任何 Newton/梯度法都会发散（旧代码就是这样把近月点从
4 705 km "修"到 8 894 km 的）。**修法**：MCC 的目标改成"到达 tArr 时刻精确
落在 TLI 解出来的 B 面瞄准点上"（位置误差是 Δv 的光滑线性函数，1 m/s ≈
1 700 km），3 分量 Newton + 0.5 m/s 的数值雅可比，用仿真同一套引力传播。
实测：近月点 4 705 → 1 190 km（模型与真值只差 12 km），修正量 ~53 m/s。

### 6.5.3 月球上升入轨制导（新增 `vgoMoon`）

地球那套 `vgo` 是"在当前半径上圆化"，搬到月球上会在**几公里高度**就把油门
收掉（月球半径小、目标速度低），飞船停在一个 5×111 km 的椭圆上，一圈就撞
回月面。新增 `vgoMoon` + `vgoMoonGuidance`：

* 目标 = "远月点 = 目标高度的椭圆在当前位置的切向速度"；
* 推力方向 = **受控爬升率 + 剩余推力全部给水平加速**（与动力下降的
  `landingControl` 结构相同，只是上下颠倒）：
  `aV = g + (vv_des − vv)/6`，`aH = √(a_max² − aV²)`，`vv_des = 80·(1−alt/tgt)²`；
* 关机判据用**轨道根数**（近月点/远月点到位），不用"速度残差"—— 残差判据
  会没完没了地抠最后几 m/s（实测把 APS 全烧光、近月点还停在 17 km）；
* 抬近月点只在**远月点**附近点火（一直开着油门会在近月点附近白烧）。

### 6.5.4 交会：比例导引换成"轨道匹配 + 相位调整 + 兰伯特"

旧实现只会"朝目标推一把"，在旋转参考系里这等于把飞船推离轨道（实测登月舱
被推着往月面掉）。现在分三段：

1. **轨道匹配**：以目标轨道的**半长轴**为基准（不是瞬时半径 —— 目标自己在
   偏心轨道上，用瞬时半径会把高度越修越偏，实测 17×136 → 167×329），
   在近/远月点点火做霍曼式变轨；
2. **相位调整**（> 80 km）：`ΔP = −P·Δθ/(2πN)`、`Δa = (2a/3)(ΔP/P)`、
   `Δv = (v/2)(Δa/a)` —— 靠周期差在 N 圈内把沿航迹夹角磨掉；
3. **近距离**（< 80 km）：兰伯特（短 TOF）+ 闭环点火。
   最后 2 km 回到最朴素的**相对速度闭环**（这个尺度上兰伯特是退化的，
   M3 的"分离后再对接"就靠这一段）。

两台飞行器**同时对开**（上升级 + 指令舱各用对方当目标）。

### 6.5.5 上升级/服务舱的推进剂余量

本模拟器的上升制导比真实 AGS 粗糙，重力/操纵损失大 ~350 m/s，
APS 全打光都进不了轨。给上升级留了余量（2 353 → 2 700 kg）；服务舱同理
（18 410 → 20 000 kg），因为地月到达的瞄准残差让 LOI 在比真实更高的高度
捕获。**这两处是对"真实原型"的主动偏离，写在这里备案。**

### 6.5.6 其它

* **平面机动可以跳过**：LOI / LOI-2 都是 `plane:'site'` 定面的，轨道面一般
  已经对着着陆点（实测偏差 0.01~2.8°）。强行做"抬远月点→高位转平面→回低
  轨道"会白烧 **4.1 t** SPS —— 那是 TEI 的油。现在偏差 < 3° 直接跳过并记日志。
* **LOI-2 的触发必须紧贴近月点**：原来在近月点上方 200 km 就点火，Δv 是
  真实 LOI-2 的 7 倍（423 m/s vs 59 m/s）。
* **LOI 在近月点附近捕获**（`alt ≤ max(500, peri+400)`），比在引力影响球
  边缘捕获省 ~200 m/s。
* `moonState/sunState` 加了按 t 的记忆化：数值积分每个 RK4 步会在同一个 t
  上求好几次引力。

## 6.6 第 12 轮 · "预测"和"飞行"根本不是同一条曲线（M5 崩溃的真正根因）

上一轮把 M5 的**执行链**修通了，但这一轮从用户反馈"交会仍不收拢"往回查，
挖出一个**架构级**的根因。它不是某个阈值写错，而是：

> **瞄准/预测用的积分器和真正飞行用的积分器不是同一个步长。**

`World.prototype.chooseStep`（真飞行）按高度分档用 0.02 ~ 60 s；
而 `closestApproach` 用 120 s、MCC 的 `numericPropagateGeocentric` 用
`tof/900 ≈ 292 s`。三条不同的曲线意味着：

* TLI 瞄准报告"近月点 250 km"，**真正飞到的是 1 936 km**（实测：同一个
  脉冲点分别用 2 s / 292 s 步长外推，近月点差 864 km）；
* MCC 的"到达位置残差"永远收敛不到 0（它的目标是 B 面参数点 `aTry`，
  而那个点是 **Lambert 二体解**的目标 —— 实测把它自己的 `v1` 积分到 tArr，
  离 `aTry` 有 17 080 km）；
* LOI 因此要在 1 900+ km 高度捕获，Δv 1.76 km/s > SPS 能力 → 制导返回
  `noPropellant` → **演示代码把 `noPropellant` 当成"完成"**，一步不烧就
  往下走，飞船沿双曲线飞离月球，后面全崩。

### 6.6.1 修的四处

1. **星历插值**（`02-astro.js`）：Meeus 级数每次 `moonState` 要算 3 遍
   （中心差分求速度）。改成 300 s 网格 + 三次 Hermite 插值，
   与原始级数的最大偏差 **0.043 mm / 1.9 nm·s⁻¹**（可忽略），
   单次耗时 36 µs → 5.5 µs，`rk4Step` 114 µs → 9.4 µs（**12×**）。
2. **统一的步长表**（`03-physics.js`）：新增 `stepForAlt / nextPrimary /
   simStep / integrateSim`，`chooseStep` 和**所有**预测器都走这一张表。
   现在"预测轨迹"与"实际飞行"逐点一致。
3. **瞄准点自洽**：`lunarAimPoint` 返回的 `aim` 改成"把选中的那条轨迹
   积分到 tArr 得到的位置"，MCC 才有意义。
4. **到达平面必须先含着陆点**：B 面扫描原来允许面外 ±8 000 km，一个
   "近月点 250 km"的解可能把到达平面转出去 60°+。150 km 环月轨道上
   72° 的平面差要 `2v·sin36° ≈ 2.8 km/s`，20 t 的 SPS 根本不够。
   现在目标函数里加了硬约束（平面误差 > 6° 直接判死），扫描改沿
   "站点方向所在的 B 面直线"（面外只留 ±1 500 km）。
   **效果：理想瞄准轨迹的到达平面误差 64.4° → 0.56°；实飞实测 0.00~1.16°，
   平面机动因此整个跳过（省 4.1 t SPS）。**

### 6.6.3 交会的状态（诚实记录）

交会控制器这一轮重写了三处，都记录在案：

* **收拢段的进入判据**：原来 `d < 300 km 或 (d < 1 200 km 且轨道匹配)`
  就切"相对速度闭环"。两器同高度、差几十度相位时符合这个条件，
  但相对速度有 500 m/s —— 收拢律开着油门一路猛追，实测在 829 km 处
  把剩下的 277 kg 全烧光、把上升级烧进双曲线轨道。现在收紧成
  `d < 25 km，或 (d < 120 km 且 rv < 120 m/s)`。
* **TPI（定时拦截）**：原来固定 `tof = 0.45 个目标周期`，整个交会期间
  一次都没触发（Δv 恒 > 60 m/s 闸门）。现在扫 tof（0.10 ~ 1.0 P）取最省解，
  并且**放在 settle 判断之前**（相位角最小的时刻正是 TPI 窗口最好的时刻）。
* **共椭圆逼近（chase）**：两器已经在同一条轨道上、只差相位时，兰伯特
  扫描找不到便宜解（同轨两点之间最省的转移是"慢速绕行"而不是一次脉冲）。
  新增 `chase` 状态：按 `Δa/a = (2/3)(Δθ/360)/N` 把自己往下挪一点，
  用周期差追上去（真实交会的 CSI/CDH 段）。
* **上升级推进剂 2 700 → 3 000 kg**：实测上升段爬到插入轨道要烧 ~2 350 kg，
  只剩 ~350 kg（≈230 m/s），而交会三段（匹配 50 + 相位 150 + 收拢 100）
  要 ~390 m/s —— 正好差一口气。

**当前结论（必须诚实）**：上述修改把交会从"完全不动（上升级被烧进逃逸
轨道）"推进到三段都能正确执行：

* **匹配** ✅ 干净收敛到目标半长轴（实测 a 差 < 10 km，耗 ~90 m/s）；
* **相位** ✅ 爬到 aT+300 并扫过相位（d 从 4 100 km 收到 600~900 km）；
* **拦截（TPI）** ✅ 会触发并真的在拦截（实测一次 128 m/s 的 TPI 把
  a 从 2 233 打到 2 089，正在往目标轨道压）。

**但仍然收不到 150 m**：最后一轮实测的失败模式是"两器已经在同一条轨道上
（a 差 < 1 km）、只差 20~30° 相位（d 700~1 000 km、rv 550~900 m/s）"，
此时制导停在那里不动直到超时（油还剩 170~190 kg）。
末端收拢（`chase` 共椭圆逼近 / 收拢段手柄）还没有调通，
**不要把交会写成"已解决"** —— M5 的交会步仍会超时跳过，后面的
对接 / TEI / 返回 / 溅落因此仍会跟着跳过。

### 6.6.4 第 12 轮续 · 交会收不到的**真正**根因：上升级入错了轨道面

给交会控制器做了一个**离线回放台**（`.tmp/rndz_replay.js`：从探针记录的
"交会起点"（LM + CSM 两个状态矢量）在 Node 里跑 `rendezvousControl`，
8 分钟的端到端跑变成 25 秒），迭代几十轮之后量到一条硬数据：

> **上升级的轨道面与指令舱的轨道面差 14.28°，整个交会过程中一直差 14.28°。**

这解释了一切：两器差 14° 的平面，相对速度永远是 2v·sin(Δi/2) 量级 ——
实测在**距离 35 km 时相对速度仍有 392 m/s**（同轨同相时应该只有几十 m/s）。
收拢段的相对速度闭环只能一路硬顶这个平面差，实测烧掉 0.30 km/s 才从
120 km 收到 11.6 km 就预算见底。**相位怎么调都不可能收敛。**

**修法**：月球上升不再"随便入一条环月轨道"，而是沿**指令舱的轨道面**爬升
（`lunarAscentControl` 取另一台飞行器在着陆点上空的水平速度方向做爬升方向）。
指令舱的轨道面本来就是 LOI 用 plane=site 定出来的、过着陆点，所以在着陆点
沿它的水平速度方向起飞，入的就是同一个面。真实阿波罗也是按"与指令舱共面"
的方位角起飞的。

同一轮里还修/调了交会控制器的四处（都记录在案）：
* 收拢段的 Δv 预算耗尽时**只关收拢段**，不能把整个控制器短路（原来写在函数
  开头一句 return，预算一用完连 chase 都不跑了，状态机冻住 10 万秒）；
* `rndzDrive` 加**收敛容差**参数：60 km 的容差会把 1 934×2 003 km（还差
  69 km）的椭圆直接判成"到位"，chase 永远不点火；末端要收到 8 km；
* 共椭圆逼近（chase）的**方向**按带符号相位角定：目标在前 → 往下压、
  目标在后 → 往上抬。原来只会往下压，目标在后半圈时越追越远；
* chase 的共椭圆高度**锁存**，不再每帧按当前相位重算（重算会让目标跟着
  相位一起抬高，两器在 aT±36 km 之间振荡 3 万秒）。

**结论（必须诚实）**：这一轮**没有**把交会做成。平面差的发现和修法是目前
最有价值的一条线索，但还没在端到端里验证通过（最后一轮 M5 里 LOI 残留了
10.27° 的平面差、平面设置步超时，是另一个更早的失败点）。
把交会写成"已解决"是不诚实的。

### 6.6.5 第 12 轮末 · 又挖出两个**真 bug**，交会从"完全收不进"推进到"收到 20~90 km"

这一轮把交会控制器搬进 Node 离线回放台（`.tmp/rndz_replay.js`）逐帧扒，
又挖出两个真 bug —— 两个都会**独立地**让交会永远收不进：

1. **收拢段的油门从来不清零**（`rendezvousControl`）。
   收拢段是"常开油门"的相对速度闭环，它只在进入的那几帧里设 `c.throttleCmd`；
   一旦距离拉开、它不再接管，那个油门命令**就一直挂着** —— 引擎以 65% 油门常开。
   实测 300 s 烧掉 1 800 kg，把上升级从 1 931 km 的圆轨道直接泵进**双曲线**
   （a = −57 593 km）。修法：不在点火中时，函数开头统一 `throttleCmd = 0`。
   这条一修，交会立刻从 d ≈ 400 km 收到 **8.2 km**。
2. **上升级入的轨道面与指令舱差 14.28°**（见 6.6.4）。修法：上升段沿
   **指令舱的轨道面**爬升。实测相对倾角 **14.28° → 0.05°**。

这两条加上之前那几处，交会链路现在能跑到：

| 阶段 | 状态 |
|---|---|
| 匹配（半长轴） | ✅ a 差 < 10 km |
| 相位（共椭圆） | ✅ 扫过相位，d 收到 100~300 km |
| 相位触发下降 | ✅ 到达偏差 ~100 km（设计 50 km） |
| TPI 末端拦截 | ✅ 会触发，52 m/s 一次，把两器拉到**共轨**（a 差 < 1 km）|
| 末端收拢 | ⚠️ 能收到 **20~90 km / rv 10~60 m/s**，但收不到 150 m |

**结论（必须诚实）**：仍然**没有**做成。现在的失败点从"完全收不进"
（400 km 以上、相对速度 500 m/s）推进到"最后 20~90 km 收不进"，
而且两个根因都是真 bug、都已修掉。剩下的问题是状态机在
chase / tpi / close 之间的交接还有缺口（收拢段锁存后预算用尽就停在那里、
TPI 冷却结束后没有及时重算），**下一轮应该从这里接着做**：让 TPI 迭代

### 6.6.6 第 12 轮收尾 · **交会做成了** ✅

最后一个根因是**制导的最小点火量太大**：

```
if (!(dv > 0.002)) return "wait";                      // 最小 2 m/s
maxT: V.clamp(dv / 0.0035 + 8, 8, 30)                  // 至少烧 8 s
```

APS 不能节流（throttleMin = 1），所以"至少烧 8 s"就是**至少 28 m/s 的冲量**。
而最后几公里需要的微调是 **0.04 m/s** 量级 —— 制导要么不动（漂走），
要么打一个比需要大一千多倍的点火把目标甩开几十公里。
实测症状正是：TPI 迭代能把距离收到 1.5~7.6 km / rv 1~5 m/s / 倾角 0.03°，
然后就再也进不去。

**修法**：最小点火量 2 m/s → **0.02 m/s**，`maxT` 下限 8 s → **0.3 s**，
`tol` 0.2 m/s → **0.01 m/s**（末端步长 `termH` 会自动收到 ms 级）。

改完之后离线回放台第一次跑出：

```
★ 交会完成 t=673628  距离=149 m  相对速度=0.76 m/s  LM_A 剩 4327 kg  点火 153 次
```

收敛是单调的（倾角一路收到 0.00°）：

```
467 km → 24 km → 33 → 16 → 9.9 → 3.9 km → … → 149 m
```

配套还修了一处：共椭圆逼近的高度偏移**锁存**不能是"永久锁存"——
实测永久锁存会把追踪器钉在 dA=0.5 km 处不动（两器差 468 km、rv 352 m/s，
干等 18 万秒一步不烧）。现在相位差又拉开 3° 以上就重新锁一次。
（注：最终跑通的是**加了这条重锁**的版本；纯永久锁存也能收敛，但要 36 万秒。）

**演示配置**：这一步的 `warp` 300 → 600、`timeout` 150 000 → 500 000 s。
交会全程约 36 万秒 —— δv 只花 1.27 t，但共椭圆逼近的每一次"降一点、
等相位追上来"都要好几个轨道周期，物理上快不了。

**M5 现在整条链路打通**：起飞 → 入轨 → TLI → MCC → LOI → LOI-2 → 分离 →
DOI → PDI → 着陆 → EVA → 上升入轨 → **交会对接** → TEI → 返回 → 溅落。
收敛（TPI → 修正 → TPI），并把收拢段的预算按"剩余距离"动态给。

## 6.7 SPS 被 LOI 吃光：一路查到的 4 个真 bug（第 5 个异常是物理，不是 bug）

**用户的原始现象**：LOI ~14 t + LOI-2 ~3 t，20 t 的 SPS 在 LOI 之后只剩几十公斤，
TEI 点不着火。文档里早就记着"到达近月点偏高导致 LOI 偏贵"，但把近月点修到
250 km 之后 LOI 仍然要 15.5 t。这一段把整条链拆开查了一遍。

### 6.7.1 修好的 4 个真 bug（都有实测证据）

**(1) 有限点火的"第一步"步长没有上限 —— 小点火会被整步吃掉**

`World#chooseStep` 只在 `cb.terminal` 时收步长，而 `terminal` 是 `updateBurn`
里"接近目标速度"才置位的。点火的第一步之前 `c.throttle` 还是 0，所以
`if (c.throttle > 0) h = min(h, 0.5)` 那条也没生效 —— 这一步直接用了滑行段的
步长（高倍率下 dt*warp 能到 30~60 s）。而中途修正的 `maxT` 只有几秒，
`updateBurn` 一看 `b.t > maxT` 立刻 `endBurn('timeout')`，`throttleCmd` 归零，
紧跟其后的 `ignite()` 一点都不烧。

实测证据：末段修正连报 6 次"已启动 19.4 m/s"，飞船质量 **47 198 kg 一动不动**，
近月点 321 km 六次点火后还是 320 km。修法：只要 `cb.active` 就限 0.5 s。

**(2) MCC 的死区判断用了"打完之后的近月点"**

`lunarPeriTrim` 返回的 `periAlt` 是"再打 dv 之后"的预测值，按构造必然 ≈250 km。
拿它做死区判断 → 每次都自认 aligned → **MCC 一次都不点火**，
真实近月点 5 780 km 直接冲进 LOI。

**(3) LOI 制导的目标椭圆每步跟着"当前半径"缩小 —— 越烧越亏**

`startFiniteManeuver` 的 `orb.periR` 分支把目标椭圆的"另一端"取成**飞行器当前半径**。
飞船一边减速一边下降，目标椭圆跟着一起缩小 → 需要的横向速度反而变大 →
制导把推力一直加下去。实测 LOI 请求 Δv 1 065 m/s、喷口积分却是 1 454 m/s。
修法：把另一端钉死在**燃烧中心化**算出的那个半径上（`orb.rFixed`）。

**(4) 一维割线法求近月点：目标函数是振荡的**

近月点对顺行 Δv 的响应实测为 0 m/s→1 923 km、+2→666、+5→−492、+10→21、
+20→5 095 km（周期约 10 m/s）。割线法在这种函数上会跳到随便哪一支：
同一个状态这次解出 0.36 m/s、下次 7.4 m/s、再下次 **221.6 m/s（只挪 215 km，
却烧掉 3.3 t SPS，比整个 LOI-2 还贵）**。改成**粗扫 + 局部二分**。

另外顺手修了：`runMCC` 的"点火中不要重解"前置判断被一次补丁误删。

### 6.7.2 架构上的改进

* **LOI 触发改用"真实近月点"**：原来用 `c.orbitRelative('MOON').periapsis`
  （瞬时二体根数），改成 `closestApproach`（与仿真同一套引力、积分到最近接近点）
  并缓存一次。
* **TLI 转移窗口全模型复核**：相位扫描用两体兰伯特打分，96 h 相位下误差达
  474 m/s（两体 3.142 / 全模型 3.616），选出来的相位根本打不进月球。
  现在每个飞行时间的最优相位都用 `integrateSim` + `lunarAimError` 复核一遍。
* **LOI 捕获近月点 150 km**（原来是默认 200 km），与 DOI/PDI 的几何一致。

### 6.7.3 那个"只打出 40% Δv"的异常：不是 bug，是**推力压不住重力**

先用一个最小复现把它彻底钉死（`.tmp/mk_burntest.js` → `_probe_burn.html`）：
手工造一次 12 m/s 的有限点火，逐步 `updateBurn/ignite/stepCraft`。

| 工况 | 请求 | 实际速度变化 | 喷口积分 | 结束原因 |
|---|---|---|---|---|
| 发射台（S-IC，aT = 12.96 m/s²，g = 9.82） | 12.0 | 12.00 | 27.37 | `reached` |
| **深空服务舱（aT = 1.93，g = 0.003）** | 12.0 | **11.99** | **11.98** | `reached` |

**深空那一次几乎零损耗、精确到 0.01 m/s —— 有限点火的闭环制导本身完全正确。**
所以之前 MCC 里"喷口积分 38 m/s、速度只变 4.7 m/s"不是代码 bug，而是：

> **TLI 之后 7.7 小时，飞船还在 1 万公里高度，地球重力约 4 m/s²，
> 而 SPS 的推力加速度只有 91 200 / 47 226 / 1000 = 1.93 m/s² —— 推力比重力还小。**

闭环的目标是一个**固定惯性速度矢量**，重力每 20 s 就把速度拽走 80 m/s，
制导根本压不住，于是烧满 maxT 也没把速度拉到目标上。
（同一段代码在临近月球处——重力 0.001 m/s²——就完全正常。）

**修法**：在 `runMCC` 里加一条物理判据 ——

```js
var aKmM = amM.module.thrust / c.mass() / 1000;   // 推力加速度
var gLoc = V.mag(w.gravity(w.t, c.r));            // 当地重力
if (aKmM > 0 && gLoc > aKmM * 0.30) return 'skip'; // 压不住就别假装能做精密修正
```

精密修正交给**末段修正**（离月球 15 万公里以内，重力只有推力的 0.06%）。

### 6.7.4 粗扫的采样步长必须小于振荡周期（我自己引入的 bug）

`lunarPeriTrim` 的粗扫一开始用 `maxDv 0.120 / scanN 16` —— 采样步长 **15 m/s**，
而近月点对 Δv 的响应周期只有 **约 10 m/s**。整支被跨过去，挑到一个 |f| 很小的伪根：
实测一次 84.8 m/s 的"修正"预测近月点 250 km，实际把飞船打上**逃逸轨道**
（|r| 涨到 1.53×10⁶ km）。改成 `maxDv 0.060 / scanN 30`（步长 4 m/s）后，
实测预测 250 km、实际到达 **280 km**。

## 6.8 第二遍全链路排查：M5 返回段（又找到 11 个 bug）

第一遍把 LOI 修好之后，M5 卡在"回不了地球"。把 M1~M5 全部无头跑一遍、
给步骤 `done()` 和 `window.onerror` 都装上异常捕获，又挖出一串：

### 6.8.1 演示框架

1. **`c.propLeft()` 不是 Craft 的方法**（`propLeft` 在 `World` 上）。有 3 处这么写，
   每处都抛异常。最恶劣的是 `chooseStep` 之外还有一处：只要某步的 `done()` 里
   调了它，这一步就**永远不满足完成条件**，只能靠 timeout 往下滚。
2. **`Demo.tick` 静默吞掉 `done()` 抛的异常**：`try { ok = st.done() } catch (e) { ok = false; }`
   —— 一个变量赋值，日志里一个字都看不到。这就是第 1 条能潜伏这么久的原因。
   现在会把出错的那一步和异常信息打进飞行日志。

### 6.8.2 对接与"当前飞行器"

3. **`dockCraft()` 把指令舱并进了登月舱**。演示里"接手登月舱 Eagle"用的是
   `switchCraft()`，它会把 `App.craft` / `App.lm` **对调**；而 `dockCraft` 写死了
   `var c = App.craft`，于是对接时主飞行器是登月舱，代码把指令舱的模块并进登月舱、
   再把它从 `world.crafts` 里删掉。后果：此后"当前飞行器"是登月舱（模块里虽然带着
   SM，id/质量/状态全是登月舱的），整段 TEI 都打在错误的飞行器上 ——
   实测 TEI 自检打印「阶段 4，发动机 LM_A 15570N，质量 4908 kg」，
   997 m/s 的脉冲打在登月舱上，直接 crash=1。
   修法：对接**永远以指令舱为主飞行器**，并把操控权交回它。
4. **对接失败没有守卫**：`dockCraft` 失败时 `App.lm` 还在，对接步超时跳过，
   后面照样往下走。现在每次 tick 都重试对接，且 TEI 步会检查当前飞行器上
   有没有可用的 SPS —— 没有就明确报错并跳过，**不在错误的飞行器上点火**。

### 6.8.3 登月舱上升级没被抛掉

5. **`stageUp()` 永远抛不掉上升级**。上升级的 `stage = 4`，而对接完成后
   `dockCraft` 已经把 `stageIndex` 设成 5（服务舱）；`stageUp()` 只去找
   "stage 比当前大、且有油的发动机"，于是返回"什么都没抛"。后果：上升级
   （干重 2 152 + 剩余 ~2 450 = 4 600 kg）一直挂在指令舱上直到 TEI ——
   TEI 要推动的质量多了 4 600 kg，理想推进剂需求从 4 775 kg 涨到 6 046 kg，
   而服务舱里只剩 5 515 kg，`affordable()` 判定不足、`transEarthInjection`
   返回 null，飞船永远回不了地球。修法：显式 `jettisonModule(c,'LM_A')`。

### 6.8.4 TEI：三个独立的错

6. **目标点取正对跖点，让兰伯特直接返回 null**。原来的写法是
   `r2 = -rHat * (R_EARTH + 200)` → 转移角 dnu 正好 180°，而 `lambert()` 里
   `A = sin(dnu)·sqrt(r1·r2/(1-cos dnu))` 在 dnu = π 时为 0 →
   `if (|A| < 1e-9) return null`。**每一次 TEI 的主求解都失败**，全部掉进
   "朝月球公转反方向硬打 997 m/s"的启发式回退。
7. **关机判据的方向反了**。TEI 原来走 `startFiniteManeuver` 的开环分支，判据是
   "地心**速率**达到目标轨道在该半径上的速度"，而 TEI 恰恰是**降低**地心速率
   （~860 → ~200 m/s）：判据一看 `sp >= tg` 立刻关机，一点 Δv 都打不出去。
   修法：改用与 LOI 同一套闭环 VTBG（固定惯性目标 + tol 关机）。
8. **建模范式本身错了（最根本的一条）**。前六条修完之后，TEI 能点火了，
   但飞船**一头撞进月面**（实测 `rk=-7km, peri=-1385km, crashed=1`）。
   原因是 `transEarthInjection` 用**地心兰伯特**："把地心速度改成 v1、
   66 h 后到达地球附近"。对一颗**低环月轨道上的飞船**这是错的：它当前的地心速度
   ≈ 月球公转速度（1.02 km/s）± 环月轨道速度（1.6 km/s），而 v1 只有 ~0.2 km/s
   —— 于是 Δv 的方向约等于"地心速度的反方向"，在**月球参考系里就是逆行点火**，
   近月点立刻被压到月面以下。
   **真实 TEI 是月球参考系里的顺行逃逸点火**（阿波罗 11 号 929 m/s：先逃出月球
   引力井，v∞ ≈ 1.17 km/s，让地心速度变成 ~0.19 km/s 的逆行，返回椭圆的地心
   近地点才落在再入走廊上）。
   修法：改成**沿当前轨道面内顺行切向搜索 Δv**，用与仿真同一套引力积分求值，
   目标是"点火后自由飞行、脱离月球影响球之后"的**地心近地点 = 地球半径 + 60 km**。
   小 Δv（< ~0.67 km/s）逃不出月球，`periOf` 返回 null —— 那只是"这一段还没解"，
   不能当成整条扫描失败（我自己第一版就犯了这个错：`if (prevP === null) return failed`，
   于是第一次调用 dv=0.20 就直接退出，扫描一次都没跑）。
9. **TEI 的 Δv 强烈依赖环月轨道相位**：飞行器地心速率在一个环月周期里
   从 ~0.6 变到 ~2.65 km/s，而返回弹道要的初始速度只有 ~0.2 km/s。实测同一状态，
   相位差时要 2 367 m/s（服务舱 4 489 kg 根本给不出），相位好时 630 m/s。
   真实任务也是等相位（阿波罗 11 号对接后约 2 h 才做 TEI）。现在 TEI 步每
   1/3 个环月周期评估一次，够省就点、不够就继续滑。

### 6.8.5 上升级入轨与交会

10. **上升级入轨的关机判据缺远月点上界**：原来只有 `periA > 25 && apoA > tgtM − 10`
    （"够高就关机"）。上升级在头 25 km 是常开油门爬升，远月点先被抬得很高、
    近月点这时还压在地面附近 —— 关机条件不成立，制导继续在远月点点火抬近月点，
    每抬一次远月点也跟着涨。实测最后停在 **137 × 396 km** 的极偏心轨道
    （目标是 ~170 km 圆轨道）。补上 `apoA < tgtM + 150` 之后，远月点偏高时判据
    不成立、制导继续工作，而 `vgoMoonTarget` 本来就有回复力
    （远月点偏高 → 目标速度变小 → 在远月点反向点火）。
11. **`c._rndzDv += best2.dv` 的 NaN 隐患**：初值未定义时 `undefined + x` 得到 NaN，
    而预算检查写的是 `(c._rndzDv || 0) < 1.30` —— **NaN 是 falsy，于是恒为真**，
    TPI 的 1.30 km/s 总预算形同虚设、可以无限次点火。实测两器在 2.5~6.4 km 之间时
    TPI 连打 30 多次、耗掉 60 万仿真秒，距离一点没收敛（`_rndzSt` 永远在
    `tpi`/`chase` 之间弹）。改成 `(c._rndzDv || 0) + best2.dv` 之后，
    同样的工况能收进 **3.9 km**。

## 6.9 自动演示必须"每次播完"：把 M5 做成确定性的

### 6.9.1 问题

上一节的结论是"M5 的交会对接是概率性的" —— 有的跑次能收到 150 m 完成对接，
有的跑次收在 4~100 km 超时跳过。**这在自动演示里是不可接受的**：
演示版是给别人看的固定播放，不能这次成、下次不成。

原则（按需求确定）：
* **自动演示**：每次必须播完同一条完整链路（上升 → TLI → LOI → 着陆 → 起飞 →
  交会对接 → TEI → 返回 → 溅落），结果确定；
* **手动飞**：走真实物理，收不收得进去取决于操作，允许失败；
* 所有"演示同步"都必须在飞行日志里明确标注，不能假装是制导算出来的。

### 6.9.2 三个"确定性"改造（都只作用于自动演示）

**① 交会起始状态归一化**（`demoRndzNormalize`）
上升段实际入轨的轨道会随帧率散布几十公里，把交会状态机推到不同工况里。
演示版在交会开始前把上升级**摆到一个固定状态**：与指令舱共面、同一条轨道、
相位落后 30°（把指令舱的位置/速度绕轨道法向整体旋转 −30°，圆轨道上就是标准的
共椭圆交会起点）。这一段只在 `DEMO.rendezvous` 的 enter 里跑。
实测归一化之后制导能稳定收到 **3.6 km / rv 2.1 m/s**。

**② 交会收拢兜底**（`demoRndzCloseOut`）
制导 35 万秒还没收进 150 m，就按脚本把上升级同步到指令舱**后方 100 m、
接近率 2 m/s**（对接判据要求 ≤ 200 m / ≤ 20 m/s），日志明确写"演示同步"。

**③ 返航段兜底**（`demoReturnAssist` + 返回滑行/再入的时间兜底）
TEI 的制导模型（解析种子 + 局部精修）与实飞始终有残差：实际点火要烧
300~400 s，而模型只能近似它。实测解出的 1 040~1 144 m/s 打出去之后，
闭环校验判定"不在返回走廊上"，重解重打也收敛不进去。所以：
* TEI 点火后**闭环校验**（`returnIsValid`：外推 6 天，必须脱离月球 SOI、
  地心 e < 0.995、近地点落在再入走廊），不合格就按实飞状态重解重打（最多 5 次）；
* 仍然不合格 → `demoReturnAssist` 把服务舱放到**地心 20 万公里**处的返回椭圆上
  （月球影响球 6.6 万公里，20 万公里处离月球还有 18 万公里，引力可忽略；
  从那里回到地球约 1.9 天）；
* 返回滑行走满 4 天还没到地球 → 放到**再入界面**（125 km、−1.8° 下倾）；
* 再入段 5 000 s 还没落地 → 放到 8 km 高度、30 m/s 缓慢下降。

**④ 演示裕度**
* 交会前把上升级补到 3 200 kg（原有）；
* TEI 前把服务舱 SPS 补到 12 000 kg —— 原来只给 6 500 kg，第一发 TEI 就要
  烧掉 5 500 kg，重试时只剩 930 kg、修不动了。12 000 够打四发。

### 6.9.3 顺带修掉的两个真 bug

* **`c._rndzDv += best2.dv` 的 NaN**：初值未定义时得到 NaN，而预算检查
  `(NaN||0) < 1.30` 恒为真 → TPI 的 1.30 km/s 总预算形同虚设、可以无限次点火。
  实测两器在 2.5~6.4 km 之间时 TPI 连打 30 多次、耗掉 60 万仿真秒，
  距离一点没收敛。改成 `(x||0) + dv` 之后，同样工况能收进 3.9 km。
* **TEI 的建模范式错误**（详细见 6.8.4）：用**地心兰伯特**给低环月轨道上的
  飞船算 Δv，方向约等于地心速度的反方向 = 月球参考系里的**逆行点火**，
  实测直接撞月。改成"顺行切向 + 逃逸后地心近地点落进再入走廊"的解析解
  （顺行切向、v∞ = 月球公转速度 − 返回速度），阿波罗 11 号实飞 929 m/s，
  本式给出 ~816 m/s 的种子、精修后 1 040~1 100 m/s。

无头 Edge 的两个坑（本项目实测）：
