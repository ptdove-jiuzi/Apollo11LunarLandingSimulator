# 13 · 专家答复：发射方位角与到达面约束

> 答复 `11-M5-TLI阻塞问题书` §4.4/§4.5 与第 12 轮提出的"面修正 83 m/s 归因于方位角 hack"。
> 日期：2026-10-15。

## 0. 两句话结论

1. **`azimuthGuidance = 69.4` 不是 hack，它是"平面在 v_rel ≈ 1.5 km/s 就被锁定"这个模型行为下的正确方位角。** 真实 72.058° 对应的是"平面在接近关机速度时才锁定"。要改用 72.058°，必须改锁定时机 + 加平面闭环，只改数字一定掉倾角。
2. **那 83 m/s 极不可能来自方位角。** 方位角只通过倾角影响停泊面，而 32.55° vs 32.521° 只差 **0.08°**，折算到月球只有约 **1.5 m/s**。83 m/s 的真正来源是 **TLI 段"到达面 ≤ 0.1°"这条过强的约束**，见 §4。

---

## 1. 先把物理讲清楚：为什么 69.4 和 72.058 都对

发射方位角 β 是**地固系**（相对地心的水平速度方向）。惯性速度 = 相对速度 + 自转携带速度：

```text
v_i = v_rel · u(β) + ω × r
```

LC-39A（φ = 28.5729°，R = 6378.137 km）自转携带速度：

```text
v_E = ω · R · cos φ = 7.292115e-5 × 6378.137 × 0.878288 = 0.40846 km/s（正东）
```

于是惯性方位角：

```text
A_i = atan2( v_rel·sin β + v_E , v_rel·cos β )
```

停泊倾角与惯性方位角的关系（教科书瞬时式）：

```text
cos i = cos φ · sin A_i
```

对 i = 32.521° 反解：**A_t = 73.752°**（东北分支）。

**关键点：`A_i` 强依赖 `v_rel`。** v_rel 小时，0.408 km/s 的正东分量占比大，把 A_i 大幅推向正东、倾角被拉低。所以同一个 β，在不同速度锁定平面，得到完全不同的倾角。

### 数值验证（全部可复算）

| β | 锁定速度 v_rel | A_i | 得到倾角 i | 对应 |
|---|---:|---:|---:|---|
| 69.4° | 1.5 km/s | 73.75° | **32.545°** | = 他们实测 32.55° ✓ |
| 72.058° | 1.5 km/s | 75.89° | **31.63°** | = 他们实测 ~31.5° ✓ |
| 72.058° | 7.8 km/s（关机速度） | 72.94° | **32.94°** | 超目标 0.42° |

第一、二行精确复现了他们观测到的两个数，说明诊断模型是对的：**他们的平面大约在 v_rel ≈ 1.5 km/s 就锁定了。**

反解这个锁定速度：

```text
v_commit = v_E · cos A_t / sin(A_t − β) = 0.40846 × 0.27980 / sin(4.352°) = 1.506 km/s
```

根因在 `03-physics.js` 的 `launchGuidance`：

```js
var hdir = V.mag(vh) > 0.03 ? V.unit(vh) : gs;   // 0.03 km/s = 30 m/s！
```

相对水平速度一超过 **30 m/s** 就不再指令方位角、改跟踪当前方向（重力转弯）。也就是说方位角只在起飞最初几秒起作用，平面在极低速度下就被 commit——那里自转项完全主导。69.4° 正是为这个 1.5 km/s 锁定速度配的正确补偿。

**所以：69.4 不是随手凑的 hack，它是"在错误时刻锁定平面"的正确补偿。真正该修的是锁定时刻。**

## 2. 正确实现 72.058° 的做法

三件事一起做，缺一不可。

### 2.1 提高交接门限（必须）

把 `0.03 km/s` 提高到 **5～7 km/s** 区间（用相对水平速度判据），让方位制导一直握到接近关机速度。预期：

- 锁定速度 5 km/s → 72.058° 给出 i ≈ 32.2°
- 锁定速度 7 km/s → i ≈ 32.55°
- 锁定速度 7.8 km/s → i ≈ 32.94°

即：**锁定越晚，72.058° 越接近真实倾角。**

### 2.2 加平面闭环（必须，不能省）

由上表可见，即使锁定在关机速度，静态 72.058° 也只给到 32.94°，**比 32.521° 高 0.42°，超出 ±0.2° 闸门**。真实任务的方位角在上升段是变化的，静态方位角原理上补不齐，必须闭环。

实现（改动很小，复用现有 `rotateAbout`/`rodrigues`）：

```js
// 1) 目标面法向：由发射台位置 + parkingInclination + 东北分支唯一确定
//    n̂ ⊥ r_pad，n̂·ẑ = cos(32.521°)，取东北（顺行）分支
//    注意：给定 i 与台位后 n̂ 唯一，没有其它自由度 —— 这正是"倾角对了面就对了"的原因
function targetPlaneNormal(rPad, incDeg) { /* 见 §3 公式 */ }

// 2) 每步算当前面法向与目标面的夹角（绕 r̂ 的有符号角）
var nNow = V.unit(V.cross(c.r, c.v));
var nTgt = targetPlaneNormal(c.r, APL.SITE.parkingInclination);
var sigma = Math.atan2(V.dot(V.cross(nNow, nTgt), V.unit(c.r)), V.dot(nNow, nTgt));

// 3) 把指令的水平方向绕 r̂ 旋转 sigma —— 旋转速度方向 sigma 会同样旋转面法向 sigma，1:1 对应
var hdir = (V.mag(vh) > HR ? V.unit(vh) : gs);
hdir = V.unit(rotateAbout(hdir, V.unit(c.r), sigma * GAIN));   // GAIN 从 1.0 起，振荡就降到 0.5
```

之所以有效：绕 `r̂` 旋转速度方向 σ，会把 `r × v`（面法向）也旋转 σ，所以这是**1:1 作用在真正重要的那个量上**，且对"平面何时锁定"完全不敏感。

### 2.3 清理常量

```js
azimuth: 72.058,             // 真实值，保留：显示、日志、以及上面 gs 的基准方向
// azimuthGuidance: 69.4,    // ← 删除
```

`03-physics.js` 的 `launchGroundDir` 改成读 `SITE.azimuth`。

## 3. 目标面法向的构造（供直接抄）

设台位单位向量 `r̂`，`ẑ = [0,0,1]`，`φ` = 台址纬度：

```text
N̂ = normalize( ẑ − (ẑ·r̂) r̂ )        // 当地北，水平
Ê = normalize( ẑ × r̂ )               // 当地东（注意：Ê = N̂ × r̂）
cos ψ = cos i / cos φ                 // i = parkingInclination
n̂  = cos ψ · N̂ − sin ψ · Ê            // 东北分支（顺行）
```

顺行方向（用于显示/校验）：`v̂ = n̂ × r̂`，若 `v̂·Ê < 0` 取反；其方位角应 ≈ 73.75°。

**闭式反解**（随时可审计"这个 β 对不对"）：

```text
β_required = A_t − arcsin( (v_E / v_rel) · cos A_t )
A_t = 73.752°，v_E = 0.40846 km/s
```

把当前模型的 β 和实测锁定速度代进去，就能判断它是补偿还是 hack——本次代出来的 1.5 km/s 与两个实测倾角完全对上。

## 4. 重要更正：83 m/s 不是方位角造成的

按上面的公式，β = 69.4（现行）得到的停泊面与真实任务差多少？

停泊面由 **(i, 台位, 东北分支) 唯一确定**——没有其它自由度。所以 β 只能通过 i 影响停泊面：

| | i | ψ | 面法向偏差 |
|---|---:|---:|---:|
| 真实任务 | 32.521° | 16.169° | — |
| 现行模拟 | 32.552° | 16.249° | **0.080°** |

0.080° 的面差，在月球处（v ≈ 1.09 km/s）修正代价约：

```text
2 × 1.09 × sin(0.040°) ≈ 1.5 m/s
```

**修好方位角最多回收约 1.5 m/s，不是 83 m/s。** 不要指望改完方位角 M5 就通。

### 83 m/s 的真实来源：TLI 段的到达面约束过强

他们现在的验收是"TLI 到达面必须含着陆点方向，误差 ≤ 0.1°"。**这不是真实任务的约束。** 真实任务里到达面是 LOI 段收拾的：

按第 12 轮的能量核算，v∞ = 1.0874 时：

```text
111 km 双曲线近月点速度        2.5470 km/s
111 × 315 km 椭圆近月点速度    1.6707 km/s
LOI-1 理想值                  876.3 m/s
真实 LOI-1                    889 m/s
差额                         12.7 m/s  ← 真实任务为对齐平面只付了 ~13 m/s，在 LOI 付的
```

也就是说：真实任务**没有**要求 TLI 的到达面精确含着陆点，它容忍约 1° 量级的到达面误差，然后在 LOI 花 13 m/s 收拾。而他们的 `lunarAimPoint` 把 0.1° 当 TLI 硬闸门，求解器只能牺牲 Δv 去换——实测面差 0.6°~1.15° 要压到 0.1°，在近月点速度 2.547 km/s 下就是几十 m/s 的量级，正好是 83 m/s 这个量级。

**建议改法**：

1. TLI 段到达面闸门从 **0.1° 放宽到 1.0°~1.5°**（只要能进 `lunarAimPoint` 收敛域即可）；
2. 平面对齐交给 LOI-1/LOI-2（`lunarOrbitAlign` 的 `plane:'site'` 已经在做这件事）；
3. 用"LOI-1 = 889 ± 50 m/s"作为总账验收——如果放宽后 TLI 降下来的 Δv 转移到 LOI 后总和仍然接近 889，就说明这条路是对的。

按这个方向，83 m/s 的大头应该能拿回来，而且拿回来的方式与真实任务一致。

## 5. 剩下的基线差：3180 vs 真实 3050

即使面约束放开，还有一层：他们的两体兰伯特在 75.9 h 窗口要 **3180 m/s**，而真实任务 TLI 是 **3050 m/s**，差约 **130 m/s**（全模型后是 3262 vs 可用 3179）。这个差不是平面问题（上面已量化），建议按顺序查：

1. **月球历表整矢量比对**：把 `moonState(10069.5)` 和 `moonState(10069.5 + 75.9×3600)` 的完整 ECI 位置/速度导出，与 JPL Horizons / DE440 对 1969-07-16～07-21 的数值逐分量比。只看 `|r| = 403692 km` 不够——距离对但方向差几千公里，兰伯特 Δv 就能差上百 m/s。Meeus 截断级数的定位精度通常够，但要确认历元常数与截断项没有引入系统偏差。
2. **出发状态比对**：把真实 S-IVB 关机状态（或由 183.2×185.9 km、i=32.521° 构造的停泊态）在 T+9861 s 的 r/v 与他们的 `r0=[6534.820, 451.849, 374.849]`、`v0=[−0.689203, 6.549541, 4.177279]` 直接比。已知他们的 `|v0| = 7.7988` 比该半径圆速度 7.7947 高 4.2 m/s（远月点被抬高到约 195 km），这只会让 TLI **更便宜**几 m/s，不解释 130 m/s。
3. **确认 3050 m/s 与 3180 m/s 是同一种量**：一个是 S-IVB 实际速度贡献（有限 347 s 燃烧、含重力损耗），另一个是脉冲等效 Δv。若定义不同，先统一再比。
4. **相位扫描范围**：真实任务等了约 1.8 圈；他们扫 5 圈。若最优相位落在扫描窗外，扩到 10~12 圈再试（成本低，先做这条排除法）。
