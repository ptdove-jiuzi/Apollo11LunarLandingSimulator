详细记录见 `05-真实轨道学与动力学改造记录.md`。要点：

- **有限推力点火**取代瞬时脉冲：新增 `World#finiteBurn / updateBurn /

  发动机累计 Δv 3 246 m/s（真实 347 s / 76 t / 3 050 m/s），重力损耗由物理自然产生。

  极轴·黄极 1.537°（真实 1.543°），极轴·轨道法向 6.658°（真实 6.688°），
  着陆瞬间静海太阳高度角 **10.34°**（NASA 10.3~10.5°；旧模型 9.79°）。
- **地月转移瞄准**：`World#lunarAimPoint()` —— B 面偏置轴必须用**月心系 v∞**
  （用"地心到达速度"是历史 bug，会让到达平面偏 8° 以上），再用 2 参数 Newton
  以仿真同一套引力做数值修正。
- **燃烧中心化**：有限点火必须提前半个燃烧时长点燃（实测不做的话远地点方向差
  24.5° = 到达月球差 15.9 万 km）。
- **MCC-2 中途修正**、**LOI-2 圆化** 成为演示脚本里的独立步骤。

14. **第 12 轮续 · 修好 EXE + 交会的真正根因（未完成）**（用户："修复这图"——
    双击 EXE 后浏览器显示 `127.0.0.1 未发送任何数据 / ERR_EMPTY_RESPONSE`；

    * **EXE 修好了**：根因是 `--windowed` 打包版里 `sys.stderr` 是 None，
      而 `BaseHTTPRequestHandler.log_message()` 会 `sys.stderr.write()` ——
      每个请求都在写日志那一步抛异常，服务在 LISTENING 但每个响应都空。
      旧的"静音"写法（给 `functools.partial` 挂 `log_message` 属性）**完全无效**。
      改成派生子类覆盖 + 服务端异常落盘 + 单实例复用（不再每双击一次就多堆
      一个常驻进程）。**实测 HTTP 200，第二次启动直接复用已有实例。**
      详见 `02-工具链.md`。
    * **交会仍未搞定**，但找到了真正的根因：**上升级入的轨道面与指令舱差
      14.28°**（离线回放台量出来的，整个交会期间不变）。14° 平面差意味着
      相对速度永远是几百 m/s —— 实测距离 35 km 时仍有 **392 m/s**，
      收拢段怎么调都收不到 150 m。已把上升段改成**沿指令舱的轨道面爬升**，
      但还没在端到端里验证通过。详见 `05` 第 6.6.4 节。
    * 顺带建了**离线回放台** `.tmp/rndz_replay.js`（用探针记录的两器真实状态
      在 Node 里复现交会），迭代一轮从 8 分钟降到 25 秒。

15. **第 12 轮末 · 又挖出两个真 bug（交会推进到 20~90 km，仍未收敛）**。

    * **上升级入的轨道面与指令舱差 14.28°**（离线回放台量出，35 km 处相对
      速度仍有 392 m/s）。改成沿**指令舱轨道面**爬升后，相对倾角
      **14.28° → 0.05°**。
    * 现状：匹配 ✅ / 相位 ✅ / 相位触发下降 ✅ / TPI 末端拦截 ✅（52 m/s 一次

16. **第 12 轮 · ★ 交会对接做成了 ★**（用户："末端收拢……想办法搞定"）。
    最后一根钉子是**制导的最小点火量太大**：
    `if (!(dv > 0.002)) return 'wait'` + `maxT: clamp(dv/0.0035+8, 8, 30)` ——
    APS 不能节流，所以"至少烧 8 s"就是**至少 28 m/s 的冲量**，而最后几公里
    需要的微调是 **0.04 m/s** 量级。制导要么不动（漂走），要么打一个比需要
    大一千多倍的点火把目标甩开几十公里 —— 症状正是"收到 1.5~7.6 km 之后就
    再也进不去"。改成：最小点火量 **0.02 m/s**、`maxT` 下限 **0.3 s**、
    `tol` **0.01 m/s**。

## 20. 2026-10-14 修界面：顶栏按钮被裁 + 启动自检污染语言

### 20.1 现象（用户反馈："字显示不完整"）

窗口一窄，顶栏最后几个按钮的文字被切：截图里「选择任务」直接被推出窗口右边缘，
「▶ 继续」被压成「▶ 继 / 续」、「新手教程」被压成「新手教 / 程」。
headless 复现（1000×700）：9 个按钮全部被 flex 压缩，最后一个完全看不见。

### 20.2 根因

`#topbar` 是**一行不换行的 flex**，`height` 写死 52px，子项 `flex-shrink` 默认 1：

* 品牌 + 4 个遥测格 + 9 个按钮的自然宽度 ≈ 1220 px，窗口一窄就挤不下；
* flex 于是把每个子项**压缩** → 按钮变窄 → 中文按钮文字**折行**；
* 压到极限后多出来的部分溢出 `#app`，被 `body { overflow: hidden }` 裁掉 ——
  这就是「选择任务」只剩一半的原因。

`app.py` 的窗口是 `width=1680, height=1000, min_size=(1180, 760)`，
所以**1180 px 是必须守住的下限**，而自然宽度 1220 px 已经越界。

### 20.3 改法（`css/app.css`，纯样式，不动逻辑）

* `button { white-space: nowrap }` —— 按钮文字永不折行（这条是止血的关键）；
* `#topbar` 改成 `flex-wrap: wrap` + `min-height: 52px; height: auto` ——
  宁可顶栏占两行，也不许出现半个字；
* `.brand / .tcell / .tbtns > button { flex: none }`，`.tgroup` 可伸缩可换行；
* 两级媒体查询：≤1180 px 压缩间距、藏掉副标题「登月模拟器」；
  ≤980 px 继续压字号和按钮内边距；
* 顺手修掉控制条同类问题：`.cgroup { flex: none }`、`.clabel { white-space: nowrap }`
  （原来窄窗口下「动作」会折成「动 / 作」）。

### 20.4 顺带发现：启动自检每次都在改语言

`index.html` 末尾的内嵌自检脚本里原本是：

```js
APL.setLang('en');   // 验证英文界面
...
APL.setLang('zh');   // ← 硬写回中文
```

后果有两个，都是用户可见的：

1. **每次开机飞行日志里都会多出两行**「── Language switched to English ──」和
   「── 语言已切换为中文 ──」，像是玩家自己点过语言按钮；
2. `?lang=en`（09-i18n.js 里明确写着"方便自动化测试"）**永远不生效** ——
   自检最后把它改回了中文，`<html lang>` 也是 zh-CN。

改法：自检**记住当前语言、切完再切回去**，并用 `APL.__silentLangSet` 让
07-app.js 的语言监听器在自检期间不写日志。

```js
var lang0 = APL.getLang();
APL.__silentLangSet = 1;
try { APL.setLang('en'); ...; APL.setLang(lang0); }
finally { APL.__silentLangSet = 0; }
```

`?lang=en` 现在真的切过去了（`<html lang="en">`，按钮文案 `Missions`），

* 之后**完全交给真实物理**：`effCdA` 的伞降阶梯（1.5 km 以下三顶主伞
  CdA=2500，伞降终速 ~6 m/s < 15 m/s 溅落容差）自己把它落进海面 ——
  SPLASHDOWN 事件由 `checkSurface` 正常触发，`landed=true` 不是脚本写的。
