# 01 · 开发规则与经验（必读）

本文 = 项目约定（不可违反）+ 踩坑记录（症状 → 根因 → 修法，全部实测过）。
违反"铁律"级规则的改动一律不接受。

---

## 1. 架构铁律

1. **Python 只做宿主**：pywebview 窗口、静态文件服务、存档/导出文件桥。
   **所有物理、AGC、渲染、UI 逻辑都在 JS 里。** 不要往 Python 里搬任何游戏逻辑。
2. **JS 按文件名前缀顺序加载**（`00-` ~ `11-`），全局命名空间 `APL`，
   **不用 ES module**（pywebview 的 file:// 场景下 module 会有兼容麻烦）。
   新文件必须排好前缀号。
3. **新增任何资源文件（图片/程序/数据）必须同步加进 `tools/build_exe.py` 的
   `--add-data`**，否则 exe 里会缺文件（源码跑没事，打包后 404）。
4. 两条渲染通道自动切换：pywebview 原生窗口（首选）→ 本地 HTTP + Edge/Chrome
   `--app=` 应用窗口（兜底）。本机 WebView2 会崩溃，所以默认走浏览器通道；
   `APOLLO11_GUI=browser|webview` 可强制，选择记在
   `%USERPROFILE%\Apollo11Simulator\config.json`。
5. 前端异常写 `%USERPROFILE%\Apollo11Simulator\ui.log`，启动过程写 `startup.log`
   —— 用户报"打不开/白屏"时先看这两个文件。

## 2. 多语言（i18n）规则

1. 词表在 `js/09-i18n.js`：`DICT.zh` / `DICT.en` **条数必须一致**
   （bughunt 会输出 `词条 zh/en = N/N` 校验，两边不一致会在英文模式露馅）。
   当前 158/158。
2. HTML 用 `data-i18n="key"` 标记；**画布上画的字也必须走 `APL.t('key')`**
   （天体名、太阳方向、图例、参考线标签……漏一个就是"半中半英"）。
3. 任务/时序的英文放同文件的 `MISSION_EN`，用 `APL.missionText(m,'field')` /
   `APL.tlText(ev,'field')` 取，**不要往 `00-constants.js` 的对象字面量里注入字段**
   （那边 brief 是跨行 `+` 拼接，正则注入极脆弱）。
4. **切语言必须重建所有运行时内容**：任务标题/副标题、推进级列表（清 `dataset.sig`）、
   下传面板、AGC 按钮、任务时序表。漏一个就出现"半中半英"。
5. **绝对不要在 bootstrap 里用 `textContent` 硬编码覆盖带 data-i18n 的按钮**
   —— 会把翻译顶掉（这是当年最隐蔽的一处英文残留）。
6. 动态拼出的句子用局部 `L(zh,en)` 包裹；支持 `?lang=en|zh` URL 参数强制语言
   （自动化测试靠它在英文态稳定复现）。

## 3. 教程与"不要自作主张"的产品规则

1. **任何"自动弹出 / 自动播放 / 自动开始"的引导一律禁止。**
   教程只能由玩家点击【新手教程】按钮或首启提示条的【开始新手教程】开始。
   （反面案例：曾做过"首次运行自动播放教程"，用户原话
   *"我什么都还没点，结果它自己就开始播放教程"* —— 立即回滚。）
   首启只允许一条**可忽略的提示条**，点【先自己看看】后永久消失。
2. 教程引擎 `js/10-tutorial.js`：每步 `{ id, target(高亮选择器), wait(事件名) }`，
   业务代码用 `APL.Tutorial.notify('事件名')` 推进；`notify()` 拒绝空事件名，
   防止 `undefined===undefined` 意外推进。
3. 宁可让玩家自己发现，也不要强行塞给玩家。

## 4. 自动演示（11-demo.js）规则

每个任务卡片【开始任务】下面有【自动演示】按钮。演示横幅 `#demoBar`。

1. **`App` 必须导出演示要用的一切接口**（`execTLI / undockLM / dockCraft /
   switchCraft / runCalculator / logLine / finishMission / setWarpValue`）。
   **带 `&&` 的防御式调用（`app().xxx && app().xxx()`）会把未导出/拼错的接口
   变成静默失败** —— 曾导致"演示看着在走流程，TLI 其实从没点过火"
   （S-IVB 只掉 667 kg，真点火该掉 80 t）。宁可让它抛异常。
2. **步骤切换后必须当帧再驱动一次 `driveGuides(dt)`**：`enterStep()` 之后新步骤
   第一帧会沿用上一步的油门/姿态，高倍率下一帧=几十秒全推力乱飞，
   实测同一套代码 3 次里坠毁 1 次。修法就是 enter 后立刻再调一次。
3. 任何"等待窗口/相位"的判据都要**保证一定能满足**，否则就是纯超时。
4. **倍率是玩家和演示共享的状态**：演示设倍率必须走 `app().setWarpValue(v)`，
   绝不能直接 `world().warp = v`（否则档位索引失配，玩家按【+】会掉档 ——
   曾表现为"演示在 ×50000 滑行时按 +，倍率反而掉到 ×2，看着像演示卡死"）。
   玩家一动倍率 `Demo.noteUserWarp()` 即接管，演示不再覆写。
5. **制导关键阶段**（步骤 warp 在 4~1000 之间：上升/入轨/LOI/动力下降/着陆/月面起飞）
   倍率上限 = 本步推荐值 ×2，超了立即限幅并写明原因；长滑行段有下限
   （不低于推荐值，防止 73 小时滑行跑成几十分钟）。
6. **演示异常中止必须显式报出来**：`Demo.stop` 区分 done/manual/stuck/crash；
   坠毁不许写"全部脚本步骤执行完毕"，而是红色横幅（`#demoBar.failed`）
   + 原因文字留 20 秒。
7. **触地后必须 `throttleCmd = 0`**：着陆后制导继续给油门 → `checkSurface`
   判"正在起飞"解除 landed → 登月舱从月面弹起来再以几百 m/s 砸下去。
8. 月球动力下降用 `P.descentGuidance(world, craft, opt)`（P63→P64→P66 三段式）；
   环月轨道面构造用 `P.orbitOverSite()`；转移窗口搜索用 `M.raanCandidates()`。

## 5. 渲染规则（06-render.js）

1. **两个正交的相机状态**：`Renderer.view`（看哪儿：system/earth/moon/craft）+
   `Renderer.mode`（'3d' 可旋转 / '2d' 垂直轨道面俯视）。视图栏 = 4 个视图按钮 +
   `#btnMode3d/#btnMode2d` 模式开关 + 预演开关。
2. **相机状态泄漏是大坑**：2D 模式会给 `cam.customBasis`（`Camera.basis()` 优先
   返回它），**其它模式必须每帧清掉**（`if (!is2d) { cam.customBasis=null;
   cam.polarAxis=null; }`）。漏了 → 3D 视图继续用"锁定轨道面"的基向量，
   拖拽彻底失效，用户看到的就是"3D 全变成 2D 了"（真实发生过）。
   判"拖拽是平移还是旋转"要用 `renderer.mode === '2d'`，不要用 view 名。
3. **画布半径/线宽一律先夹再算**：`ctx.arc` 收到**负半径**抛 `IndexSizeError` 且
   **直接打死 rAF 主循环**（页面只剩上一帧，无头日志里只显示 "Script error."，
   要 `--enable-logging=stderr --log-level=0` 才看得到真报错）。
   例：`rim = Math.min(Math.max(1, rpx*0.045), rpx*0.25)` + 半径兜底。
4. 星球绘制：**实色整圆打底（边缘=硬边界）+ clip 内的朝阳面亮部
   （渐变终点用透明色，不是背景色！）** + 一圈 ≤4.5% 半径的临边暗边 + 收紧的
   大气环。"渐变最外圈=背景色"会把整圈边缘化进背景 = 一团虚边光斑。
5. 轨道预演（`world.predTraj`）分帧计算；重算条件 = 点火 / 沿轨迹走掉 35% / 10 s。
   **别用"位置变了 1%"** —— 高倍率下每几帧就重置，轨迹永远只有一小段。

## 6. 物理 / 轨道学铁律（改参数前先对照真实基准，见 03 文档）

1. 偏心率矢量必须除 μ：`e = ((v²−μ/r)·r − (r·v)·v)/μ`。漏除 → 所有轨道根数全是垃圾。
2. **单位自检**：内部长度单位是 km、速度 km/s。曾发生 `altKm` 与 45000（米）
   比较 → 制导分支永不生效。动任何比较之前先确认两边单位。
3. `activeModule()` 按**级号**（`module.stage`）匹配，不是数组下标 —— 否则分级后点错发动机。
4. 兰伯特 F(z) 单调递增，F(4π²)→+∞，根必在 (0, 4π²) 内；二分方向别写反。
5. 发射制导必须用**地固相对速度**（扣除地球自转），否则倾角退化成发射场纬度。
6. 着陆后的飞行器要**贴合地表并随天体自转**，否则停在惯性系里被判"甩飞撞击"。
7. 月面动力下降的物理直觉：111 km 环月 v=1.63 km/s，DPS 只有 2.93 m/s² →
   下降初期"有效重力" `f = g − vh²/r ≈ 0.04 m/s²`，**飞行器几乎失重**，
   下沉率只能被 f 慢慢喂出来。制导因此分 P63 制动 → 接近 → P66 终端三段，
   且竖直要比水平慢（vBias>1），水平速度才能在还有高度时收干净。
8. **停泊轨道的面必须包含 TLI 到达时刻的月球方向**（不是发射时刻的方向），
   否则兰伯特 Δv 会是 11.5 km/s 这种荒唐值。真实任务靠发射窗口+方位角实现。
9. 飞行器 `undock`：按 `module.group === 'LM'` 拆模块建新 Craft，`flags.isLM=true`，
   RCS 对半分。对接后 `stageIndex` 切到服务舱（5），否则 TEI 会用上升级小发动机。
10. `impulsiveBurn` **只允许当前主级及更高级出推进剂**（`stage >= actStage`），
    否则会跨级偷登月舱的油，动力下降就没油了。

## 7. AGC 规则（04-agc.js / 05-asm.js）

1. 指令位域做了**规范化**（真实 AGC 操作码与地址位域重叠）：操作码 bits14-10 +
   页内地址 bits9-0，`EXTEND` 切换整张操作码表。固定 10 位地址 = 页内 + FB 选页，
   **固定常量必须放在页内 ≥ 01400**。
2. 15 位反码字（+0=0，−0=077777），16 位累加器含溢出位，端回进位加法。
3. `fetch()` 后必须 `Z = NextZ`，否则 PC 不前进 → 死循环在第 1 条指令。
4. DSKY 用文档化虚拟通道：`021o=PROG 022o=VERB 023o=NOUN 024o=R1 025o=R2
   026o=R3 027o=指示灯`，`013o=键盘(读)`，`015o=状态(读)`；
   **`030o=油门指令、031o=姿态模式、032o=分级`** 用于把 AGC 程序接到飞船
   （这是"用 AGC 开飞船"的接口，重构教程时应重点讲解）。
5. 汇编器两遍、AGC 约定**裸数字是八进制**。三个自带示例程序
   （dsky-demo / attitude-hold / lambert）必须始终保持可汇编+可执行。

## 8. 工作方法论（执行层面的规矩）

1. **同一个文件的多处修改必须分消息、按顺序逐个下发**；并行编辑会被静默覆盖，
   工具还会报"Successfully edited"。改完关键文件回读确认，不要盲信成功提示。
2. 判断"改动没生效"的排查顺序：① 回读磁盘确认改动真在 → ② 确认服务端返回的
   静态资源是新版（fetch 一次）→ ③ 再怀疑缓存/时序。
3. **一次性补丁脚本必须先用 Write 落成 .py 文件再跑**，不要用 Bash heredoc
   内联（heredoc 会吃正则反斜杠，`re.search` 恒不匹配且无报错）。
4. **断言要能失败**：写自检前先确认元素真实类型与事件绑定方式，并保证
   "去掉功能后断言会变红"。把按钮当 select 赋 value 的假通过，见过。
5. 验证脚本要写进项目内 `.tmp/`（Git Bash 的 `/tmp` 与 Windows python 不是同一目录）。
6. **稳定性判定要重复跑 ≥3 次**，单次成功不算数。
7. **关键数值要和物理预期对齐**：TLI 该掉 80 t 推进剂，只掉 667 kg 就是没点火。
8. 交付习惯：**主产物（exe）放在 present_files 第一位**；附属（截图/文档）随后。
