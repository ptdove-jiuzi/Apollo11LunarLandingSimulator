# 02 · 工具链（本项目用到的所有工具）

> 运行环境：Windows + Git Bash。每条 Bash 前先
> `export PATH="/usr/bin:/bin:/c/Windows/System32:/c/Windows:$PATH"`。
> Python 一律用 `C:\Users\user\.workbuddy\binaries\python\envs\default\Scripts\python.exe`
> （带 PyInstaller + pywebview）；需要 PIL 的脚本（make_icon.py）用
> `...\envs\videoedit\Scripts\python.exe`。

## 4. 无头浏览器探针（端到端，最可靠的验证手段）

所有探针生成器都是同一套路：复制 `index.html` 注入一段探针脚本，
探针自己 `setInterval` 驱动 `world.advance(1/60)` + `Demo.tick(simDt)`，
结果写 `<pre id="probeout">`（**别写 `#diagout`**，会被页面自检覆写）。

| 生成器 | 验证什么 |
|---|---|
| `tools/make_demo_probe.js` | 某个任务的自动演示全程（`?m=M4`；输出 STEP/DEMO-END/MISS 落点偏差/模块余量） |
| `tools/make_warpprobe.js` | 演示途中真的点 `#btnWarpUp`，验证倍率接管/限幅/横幅提示 |
| `tools/make_viewprobe.js` | 4 视图 × 3D/2D 模式矩阵：customBasis 有无、拖拽能否转、`dot(ez,轨道法向)` |
| `tools/make_render_probe.js` | 渲染正确性：`?view=earth&mode=2d` → 对齐度、轨道在屏上的椭圆比=理论值；**先 draw() 再取相机快照** |
| `tools/make_feat_probe.js` | 轨道预演轨迹（pts 数、跨度、首点偏差） |

通用跑法：
```bash
node tools/make_demo_probe.js .        # 重新生成（index.html 变过就要重生成！）
msedge --headless=new --disable-gpu --no-sandbox --user-data-dir=".tmp/x" \
  --virtual-time-budget=180000 --dump-dom \
  "file:///.../apollo11/webdata/_demo_probe.html?m=M4&n=90000" > out.html
node -e "...抓 <pre id=\"probeout\">..."
```

### 无头 Edge 的坑（重要）
1. `--virtual-time-budget` **其实会驱动 rAF**（实测 20 帧内 11 次请求），
   但探针仍然要自己 setInterval 驱动物理，才能精确控制步长、避免与页面主循环抢。
2. 无头下 canvas 尺寸会是 200×150 兜底值；截图用 `--window-size=1400,900`。
3. **页面内未捕获异常在 dump-dom 里只显示 "Script error."** —— 要看真报错用
   `--enable-logging=stderr --log-level=0`，grep `Uncaught`。
4. 截图：`--screenshot=xx.png` 配合 `--virtual-time-budget`。

## 打包版"127.0.0.1 未发送任何数据"（ERR_EMPTY_RESPONSE）—— 坑与修法

**症状**：双击 `dist/Apollo11LunarLanding.exe`，浏览器应用窗口打开后显示
`当前无法使用此页面 / 127.0.0.1 未发送任何数据 / ERR_EMPTY_RESPONSE`。
程序自己的 `%USERPROFILE%\Apollo11Simulator\startup.log` 一切正常
（"已用浏览器应用窗口打开"），`APOLLO11_HEADLESS=1` 自检也 PASS。

**根因**：`--windowed` 打包的 PyInstaller 程序里 **`sys.stderr` 是 None**，
而 `http.server.BaseHTTPRequestHandler.log_message()` 会
`sys.stderr.write(...)` —— 于是**每一个请求**都在"写日志"那一步抛
`AttributeError`，socketserver 直接把连接关掉，浏览器看到的就是"空响应"。
服务确实起来了（端口在 LISTENING），只是每个响应都炸了。

原来的代码想静音日志，写的是：
```python
handler = functools.partial(SimpleHTTPRequestHandler, directory=...)
handler.log_message = lambda *a, **k: None      # ← 完全无效
```
**给 `functools.partial` 对象挂属性不会影响实例的方法解析**，等于没静音。

**修法**（见 `apollo11/app.py` 的 `_run_http_server`）：
派生子类覆盖 `log_message` / `log_error`，并给 `ThreadingHTTPServer` 加
`handle_error` 把真正的异常写进 startup.log —— 否则打包版出问题只能看到
一句"空响应"，无从下手。

**顺带修的另一件事**：浏览器应用窗口关闭**不会**结束进程（进程还要继续
提供本地服务），所以每双击一次就多堆一个常驻进程 + 一个端口（本机实测堆到
5 个）。现在 `browser_mode()` 启动前先读 `%USERPROFILE%\Apollo11Simulator\
instance.json`，能连上已有实例就直接复用、不再新起服务。

**排查手法**（下次遇到同类问题直接照做）：
```bash
./dist/Apollo11LunarLanding.exe &      # 起进程
tasklist //FI "IMAGENAME eq Apollo11LunarLanding.exe" //FO CSV //NH
netstat -ano | grep LISTENING          # 找到子进程监听的端口
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:<port>/index.html
```
`curl` 给 `52 / Empty reply from server` = 服务在、处理请求时炸了。

## 9. 无头用法修正（2026-10-14 实测，照这节写能一次跑通）

上面第 4 节的写法是本项目早期的版本，下面这些是当天新踩出来的修正：

### 9.1 路径与命令

| 项 | 实测可用 | 常见失败 |
|---|---|---|
| Node | `C:/Users/user/.workbuddy/binaries/node/versions/22.22.2-6/node.exe`（**不在 PATH 上**，要用全路径） | 直接写 `node` → `node: command not found` |
| Python | `D:/Python311/python.exe`（在 PATH 上，含 PyInstaller 6.22.3）；备用 `~/.workbuddy/binaries/python/envs/default/Scripts/python.exe` | 用错解释器 → 找不到 PyInstaller / pywebview |
| Edge | `"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"` | — |
| `--screenshot=` / 重定向输出 | **必须绝对 Windows 路径**，如 `--screenshot='D:\...\.tmp\x.png'` | 相对路径 → `Failed to write file: 系统找不到指定的路径 (0x3)`，且**文件不会生成** |
| `--user-data-dir` | 绝对 Windows 路径 + **单引号**，且每次换新目录 | 复用被锁目录 → `--dump-dom` 输出 0 字节 |

### 9.2 每次跑无头之前先杀干净

```bash
taskkill //F //IM msedge.exe 2>/dev/null; sleep 1
rm -rf /c/Users/user/AppData/Local/Temp/edge_x      # 换一个新的用户数据目录
```

残留的 `msedge.exe` 会锁住用户数据目录，症状是 dump-dom **静默输出 0 字节**，
很容易误判成"页面挂了"。

### 9.3 `--headless=old` 也可用，而且更省事

第 4 节写的是 `--headless=new`。实测 `--headless=old` 配
`--virtual-time-budget=4000` 足够跑完页面启动 + 自检，用来做**界面/文案验证**
比 `new` 更快、更稳：

```bash
"/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"   --headless=old --disable-gpu --no-first-run --disable-sync   --user-data-dir='C:\Users\user\AppData\Local\Temp\edge_x'   --window-size=1180,760 --virtual-time-budget=4000   --screenshot='D:\...\.tmp\shot.png'   "file:///D:/AIUSE/workbuddy/阿波罗11号模拟器/apollo11/webdata/index.html"
```

**验界面一定要在 1180 px 宽度上验** —— 那是 `apollo11/app.py` 里
`min_size=(1180, 760)` 定的窗口下限，玩家能拉到的最小宽度。

### 9.4 看界面文字用 `--dump-dom` + grep，比读截图快

```bash
... --dump-dom "file:///.../index.html?lang=en" > .tmp/dom.html
grep -o 'id="btnMissions"[^<]*<[^<]*' .tmp/dom.html     # 按钮文案
grep -o '<html lang="[^"]*"' .tmp/dom.html              # 语言真的切过去了吗
```

`?lang=en|zh` 是 `09-i18n.js` 专门留给自动化测试的强制语言参数。
抓日志节点用 `id="logBox"`，抓探针结果用 `<pre id="probeout">`
（**别抓 `#diagout`**，它会被页面启动自检覆写）。

### 9.5 打包与验收（补充）

```bash
python tools/build_exe.py            # 规范入口
# 或等价：python -m PyInstaller Apollo11LunarLanding.spec --noconfirm --distpath dist --workpath build
```

* **用户可能正开着 exe**：文件会被锁。按惯例先把旧 exe
  `cp dist/Apollo11LunarLanding.exe dist/Apollo11LunarLanding_prevN.bin` 备份再打包，
  **不要杀用户的进程**（我自己起的测试进程除外）。
* 打包后**必须真启动一次并 curl**，不能只看"打包成功"：

```bash
(./dist/Apollo11LunarLanding.exe >/dev/null 2>&1 &)
sleep 12
netstat -ano | grep LISTENING | grep <PID>          # 端口是动态分配的，只能这样找
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:<port>/index.html     # 期望 200
curl -s http://127.0.0.1:<port>/css/app.css | grep -c "<你刚改的内容>"           # 确认包内是新版
```

最后那条 `grep -c` 很关键：它验证的是**打进 exe 的资源真的是新版本**，
而不是本地源码。验证完记得把测试进程收掉。
