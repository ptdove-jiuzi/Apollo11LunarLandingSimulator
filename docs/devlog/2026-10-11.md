# 2026-10-11 · 阿波罗11号登月模拟器

## 目标
做一个完整的桌面小游戏：模拟阿波罗 11 从发射到溅落，含地月轨道计算器、
5 个预设任务，并复刻 apollo-11 / virtualagc 两个仓库的功能。要求有 exe 与漂亮图标。

## 技术选型（已定）
- **Python + pywebview（WebView2）+ PyInstaller 单文件 exe**
  （`binaries/python/envs/default` 已装 PyInstaller 6.22 + pywebview 6.2.1）

## 关键实现与结论
### 月球历表（02-astro.js）
- 用 Meeus 第 47 章截断级数，历元常数取自 JD 2440419.0639（1969-07-16 13:32 UT）
- **必须加入经度天平动** Δ = L_true − L_mean，否则静海基地着陆时太阳高度角只有 3.4°；
  修正后为 **10.57°**，与 NASA 飞行计划公布的 10.5° 吻合
- 已用 Meeus 例 47.a 校验（λ=133.162655° 完全一致）

### 踩过的大坑（务必记住）
1. `M.elements()` 偏心率矢量公式漏除 μ → 所有轨道根数都是垃圾。正确：
   `e = ((v²−μ/r)·r − (r·v)·v)/μ`
2. **高度单位混淆**：`altKm` 已是千米，却与 45000（米）比较 → 制导分支永不生效
3. `activeModule()` 用**下标**而非**级号**索引 → 分级后点错发动机（点了 S-IVB 而不是 S-II）
4. `fetch()` 后忘记 `Z = NextZ` → PC 死循环在第 1 条指令
5. 兰伯特求解的 F(z) 实际是**单调递增**，且 F(4π²)→+∞，括号必须落在 (0, 4π²) 内
6. 发射制导必须用**地固相对速度**（减去地球自转），否则方位角被初始正东自转速度污染，
   倾角会退化到等于发射场纬度
7. 着陆后的飞行器要**贴合地表并随天体自转**，否则停在惯性系里会被"甩飞"判为撞击
8. `for (var k in OBJ) if (...) continue;` 后接语句 —— IIFE 不在循环体内，只执行一次
   （导致操作码表只填了最后一个键）

## 追加：月面动力下降制导（自动演示）攻关 —— 2026-10-11 深夜

用户要求「所有任务都要有一个自动演示，放在【开始任务】下面」。按钮/横幅/引擎
（`11-demo.js`）都已就位，卡点是**自动演示能不能真的把飞船安全送到月面**。
这一晚基本把这块彻底打通了：**落点偏差 28 m，剩余推进剂 420 kg（共 8200 kg）**。

### 三个真正的根因（按杀伤力排序）

1. **下降轨道根本不经过着陆点（最致命）**
   `07-app.js` 原来用 `hz = unit(cross(ms.r, ms.v))`（**月球绕地球的轨道面**）当
   轨道面，再把飞行器放在「月面经度 = 着陆点经度 − 180°」。这个平面里**没有**
   着陆点，飞行器到 PDI 时相对"指向着陆点"方向有 **555 m/s 的横向速度**，
   等于斜着从旁边几十公里掠过 —— 任何制导都救不回来。
   修法：新增 `P.orbitOverSite(world, altKm)`（03-physics.js）：
   ```
   upS  = unit(site.r − ms.r)           // 着陆点径向
   east = unit(cross(axis, upS))        // 站点东向（axis = moonFrame(t).z）
   n    = unit(cross(upS, east))        // 轨道面法向：平面含 upS
   rad  = −upS                          // 放在着陆点正对面
   tang = unit(cross(n, rad))
   ```
   绕半圈后正好从静海基地上空经过，横向速度 ≈ 0。

2. **`checkSurface` 的 0.5 km 阈值**
   `if (alt > 0.5) return;`（alt 单位 **km**）—— 飞行器只要掉到 **500 m** 以下就
   进入撞击判定，`vv > 3 m/s` 直接 `crashed`。动力下降根本不可能只在 500 m
   以下才把速度收干净。改成 `alt > 0.05`（50 m）。

3. **制导律本身的物理被想当然**
   月球 111 km 环月轨道 v=1.63 km/s，而 DPS 只有 45 040 N / 15 349 kg ≈ **2.93 m/s²**。
   于是下降刚开始时"**有效重力**" `f = g − vh²/r ≈ 0.04 m/s²` ——
   飞行器**几乎是失重的**，下沉率只能被 f 慢慢"喂"出来。
   任何按真空自由落体设计的制导都会在开头把它拽下去、或在中段把燃料烧光。
   （顺带印证：真实 Apollo 11 制动段也确实长达 ~8.6 min，落点离 PDI 约 500 km。）

### 最终的控制律（`P.descentGuidance(world, c, opt)`）
```
tgo  = clamp(2s/vh, 8, 4000)          // 水平匀减速时间
水平: aAlong = vh/tgo                 // ≡ vh²/(2s)，即自杀式制动曲线
      最低接近速度 vhMin = min(s/tauSmax, 60)
      if (vh < vhMin) aAlong = clamp((vh−vhMin)/3, −1.0, 0)   // 别停半路
      横向: aLat = −vlat/tauLat
竖直: vdReq = 2h/(tgo·vBias)          // vBias≈1.8：竖直故意比水平慢
      aV = f + (vd − vdReq)/tauV
      h < hGate(300m) → P66 终端段：aV = g + (vd − want)/2.5
落地判据: h < 1 m 且 |vUp|<0.6 且 vh<0.6 → 油门 0
```
- 关键点 1：**vBias > 1** —— 竖直比水平慢，水平速度才会"还有高度时就收干净"，
  自然进入 P66 式纯垂直下降。这正是真实 Apollo 的 P63/P64/P66 结构。
- 关键点 2：**只有 h < 50 m 才算落地**，所以必须在 300 m 以上就把水平收掉。
- Δv 账：下降段用 2134 m/s，可用 2306 m/s（Isp 311 s × ln(15459/7259)）。

### 追加：地月转移（TLI）窗口 —— 又一个大坑

演示跑通后发现 M2/M5 的 TLI 根本没点火（S-IVB 推进剂几乎没动），飞船压根没去月球。

**根因**：兰伯特求解对「起飞点相位 + 停泊轨道面」极其敏感。
- 原 M2 场景用 `raan: 1.15`（写死的 65.9°）构造停泊轨道，这个面里**没有月球**，
  解出来的 TLI Δv = **11.46 km/s**（真实 3.05）。`impulsiveBurn` 直接因推进剂不足失败。
- 我第一版「窗口搜索」只扫**整数圈**（`wait = k * period`），永远扫不到正确相位，
  最优点只有 6.88 km/s 还是不行。
- **必须连续扫描相位**（步长 ≈ 1/25 圈），并且**轨道面要含「到达时刻的月球方向」**
  （不是发射时刻的方向）。

**修法**：
1. `01-math.js` 新增 `orbitNormal(i, Ω)`、`raanForInclination(i, u)`、`raanCandidates(i, u)`
   （平面含 u 的 RAAN 有两个镜像解，场景里把两个都试一遍、取 TLI Δv 小的）。
2. `07-app.js` 的 `parking` 场景：用「到达时刻月球方向」定轨道面 + 起飞点放在
   该方向在面内的反方向。现在 `RAAN = 357.7°`，和真实发射得到的 `359.6°` 几乎一致 ✓
3. `11-demo.js` 的 `solveTLI()`：连续扫描 5 圈内每 1/25 圈 × 5 种飞行时间，
   取 Δv 最小；新增「等待转移窗口」步骤（真实 Apollo 也是等 2.5 圈）。
4. 轨道计算器页签新增【最佳转移窗口】提示，告诉玩家"现在点火要多烧好几倍"。

**结果**：M2/M5 的 TLI Δv = **3.18 ~ 3.28 km/s**（真实 3.05~3.2）✓

### 追加：最隐蔽的一类 bug —— 「接口没导出 + && 保护」

演示跑起来后才暴露出三个**一直存在**的严重问题：

1. **`App` 上根本没导出演示要用的接口**
   `07-app.js` 只导出了 `init / startMission / showMissionPicker / updateAgcRunBtn / bootstrap`。
   但 `11-demo.js` 里写的是：
   ```js
   app().execTLI && app().execTLI();     // 永远不执行 —— 没有报错！
   app().undockLM && app().undockLM();
   app().dockCraft && app().dockCraft();
   ```
   `app().execTLI` 是 `undefined`，`&&` 直接短路 → **TLI 从来没点过火、
   登月舱从来没分离过**，演示看着一步步在走，其实什么都没做（S-IVB 推进剂
   只掉了 667 kg，而真点火该掉 80 多吨）。
   教训：**带 `&&` 的"防御式调用"会把拼错/未导出的接口变成静默失败**。
   修法：补导出，并在 `enterStep` 里把异常写进飞行日志。

2. **`Craft.prototype.undock` 根本不存在**
   `undockLM()` 里调 `c.undock('LM')` —— 这个方法在 `03-physics.js` 里从来没有。
   所以「分离登月舱」按钮**从来就是坏的**（同样被 `if (!lm)` 分支吞了）。
   已实现：按 `module.group === 'LM'` 拆出模块、建一台新 `Craft`、
   `flags.isLM = true`、RCS 推进剂对半分。

3. **演示步骤切换有"残留指令窗口"**
   `Demo.tick` 里 `done()` 判定通过后会 `enterStep()` 然后 `return`，
   于是新步骤的**第一帧仍然沿用上一步的油门/姿态**。动力下降刚接通时，
   姿态还是滑行段的"顺行"、油门还是全开 —— 在 2000 倍时间加速下一帧 = 33 秒，
   等于白白烧了 33 秒的全推力顺行，足以决定"落下去"还是"砸下去"。
   实测同一套代码：三次运行 2 次成功 1 次坠毁，落点偏差 37 m ↔ 6.3 km。
   修法：抽出 `driveGuides(dt)`，`enterStep()` 之后**立刻再调一次**；
   并把下降轨道滑行倍率从 2000 降到 300（PDI 触发的时间抖动 33 s → 5 s）。
   修完连跑三次：**3/3 全部成功，落点偏差稳定 37 m**。
